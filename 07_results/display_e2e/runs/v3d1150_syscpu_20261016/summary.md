# 표시 통합 e2e — 시스템 전체 CPU(커널 스레드 포함), 앱 CPU 창 정렬 (2026-10-16)

[`../v3d1150_labwc_20261016`](../v3d1150_labwc_20261016/summary.md)와 같은 설정에 **시스템 전체 CPU**를 더해 다시 쟀다.
벤치는 커밋 `939b7ca`, `display_bench.sh` 70열이고 샘플러는 `06_tools/python/sys_cpu_window.py`다.

이번 재측정은 논문 심사 지적에 따른 것이다. 헤드라인 CPU(응용 + 컴포지터)에는 커널 스레드·softirq·다른 프로세스가 빠져 있다.

## 1. 측정 조건

- 날짜: 2026-10-16 10:15~10:28 (KST)
- 하드웨어: Pi 5, Hailo-8, PCIe **Gen3 x1**, V3D 1150 MHz
  - 측정 직전 status-reporter 점검: `v3d_freq=1150`, 실측 1150.0 MHz
  - 표시: HDMI-A-1 1920×1080@60, labwc 0.20.2
- 코드: 커밋 `2f2d3d0`. 바이너리 md5는 [`env_bench.txt`](env_bench.txt)에 있다.
- 명령: `RUNS=3 FRAMES=900 OUT_DIR=07_results/display_e2e/runs/v3d1150_syscpu_20261016 bash 06_tools/bench/display_bench.sh`
  - 콘솔 전문: [`raw/_session/bench_stdout.log`](raw/_session/bench_stdout.log)
- **창 정렬**
  - 앱은 CPU 측정 창의 시작·끝(c0·c1)에서 `YVO_PERF_CTL`/`YVO_PERF_ACK` FIFO로 enable·disable을 알린다.
  - 샘플러가 그 순간 `/proc/stat`·`/proc/schedstat`·`/proc/interrupts`·전 프로세스 `/proc/<pid>/stat`을 찍는다. 스냅샷 하나는 약 3.5 ms다.
  - 샘플러가 잰 앱 몫은 앱의 `cpu_ms_per_frame`과 1 tick 안에서 맞는다(아래 표의 "앱").
- **idle 기준선**: 실행마다 냉각 판정 뒤 10 s를 앱 없이 잰다(`raw/<run>/syscpu_idle.json`).
- **계수 한계**
  - 커널은 `CONFIG_TICK_CPU_ACCOUNTING=y`, `IRQ_TIME_ACCOUNTING` 꺼짐이다.
  - 그래서 hardirq 시간은 끊긴 태스크에 붙고, idle 중이면 잡히지 않는다. 아래 값은 **하한**이다.
  - 프로세스별 값의 해상도는 10 ms tick(900프레임에서 프레임당 0.011 ms)이다.
  - 시스템 합(`sched_run`)은 schedstat의 ns 정밀 값이다.
- 신뢰성
  - 12회 모두 `hailort.log` warning 0, error 0
  - 검출 3369, 표시 드롭 0
  - 냉각 5회, 칩 최고 77.5 °C

## 2. 결과

### 2.1 CPU 분해 (ms/프레임, 실행별 값의 3회 중앙값)

**파이프라인** = 앱 + 컴포지터 + 커널 스레드 증가분이다. 커널 스레드 증가분은 창의 커널 스레드 몫에서 idle 기준선의 같은 몫을 창 길이 비례로 뺀 값이다. 기준선의 커널 스레드는 0~0.03 ms/f로 거의 0이었다.

| 설정 | 앱 | 컴포지터 | 커널 스레드 | **파이프라인** [3회 범위] | 무관한 사용자 프로세스 | 시스템 전체(sched) |
|---|---:|---:|---:|---:|---:|---:|
| `reg_host_off` (호스트 NMS, 표시 없음) | 3.089 | 0.022 | 0.089 | **3.189** [3.067–3.544] | 0.589 | 4.030 |
| `disp_off` (GPU 후처리, 표시 없음) | 0.878 | 0.022 | 0.211 | 1.111 [1.111–1.111] | 0.600 | 1.926 |
| `disp_asap` (표시, 최대속도) | 1.622 | 0.500 | 0.389 | **2.505** [2.500–2.660] | 0.711 | 3.429 |
| `disp_source` (표시, 소스 30 fps) | 1.744 | 0.467 | 0.367 | **2.567** [2.556–2.744] | 0.822 | 3.627 |

- **무관한 사용자 프로세스**는 이 회차에서 대부분 에이전트 CLI(`claude`, 실행당 390~540 ms)와 작업 관리자(`lxtask`)다.
  - 파이프라인과 무관한 백그라운드라 파이프라인 몫에서 뺐다.
  - idle 기준선(초당 21~84 ms)이 이 프로세스들 때문에 실행마다 크게 흔들렸다. 그래서 "시스템 전체 − 기준선"(`sys_net_ms_per_frame`)은 해석에 쓰지 않는다. 한 실행은 음수였다.
- 창에서 시작해 창에서 끝난 짧은 프로세스 몫(`unattributed_ms`)은 프레임당 −0.28~+0.13 ms로, tick 양자화 수준이다.
- 앱 CPU(`cpu_ms_per_frame`)는 3.086 / 0.882 / 1.624 / 1.738이고, 컴포지터 열(수명 창)은 0.022 / 0.022 / 0.511 / 0.478이다.
  - 같은 날의 [`v3d1150_labwc_20261016`](../v3d1150_labwc_20261016/summary.md)(3.047 / 0.943 / 1.589 / 1.768)과 3회 범위가 겹친다.

### 2.2 감소율 (기준 `reg_host_off` → `disp_asap`)

| 집계 범위 | 중앙값 비 | 같은 회차 짝(run1·2·3) |
|---|---:|---:|
| 앱만 | −47.5% | −44.6 / −52.6 / −45.9% |
| 앱 + 컴포지터 | −31.8% | −27.9 / −38.4 / −29.1% |
| **앱 + 컴포지터 + 커널 스레드(파이프라인)** | **−21.4%** | **−16.6 / −29.3 / −18.5%** |

### 2.3 커널 스레드와 인터럽트

- **커널 스레드**
  - 표시 없음에서는 V3D 캐시 정리·CPU 잡 kworker 정도라 0.09~0.21 ms/f다.
  - 표시를 켜면 `kworker`의 `v3d_tfu`·`v3d_csd`(V3D 작업 제출)와 `events_unbound`(DRM 커밋 등)가 늘어 0.37~0.39 ms/f가 된다.
  - `ksoftirqd`와 irq 스레드는 0이다.
- **인터럽트**(`disp_asap` run2 기준, 프레임당)
  - Hailo MSI 7.0, V3D 7.0, HEVC 디코더 2.0, HVS 1.7, vc4 crtc 1.5
  - 함수 호출 IPI 57.7, 타이머 43.8, 총 126
  - 표시 없음(`reg_host_off`)은 총 71이고 V3D는 1.0이다.
  - 소스 페이싱은 타이머 인터럽트가 늘어 총 176이다(페이싱 대기 타이머).
- **softirq**: 횟수는 창마다 2.2만~3.8만으로 늘지만 tick 계수상 시간은 0으로 잡힌다(`softirq_ms` 0). 실제 시간은 끊긴 태스크에 붙었을 것이다.

### 2.4 지연·GPU (참고)

- 표시 지연(glass-to-glass) `disp_source`의 실행별 median은 100.08 / 90.53 / 96.66 ms이고, 평균의 3회 중앙값은 99.81 ms다.
- M5a 1080p 변환은 3.691 ms, 화면 위 변환은 3.638 ms다.
- 처리량은 34.97 / 34.97 / 34.89 / 29.90 fps다.

## 3. 결론

- **커널 스레드까지 넣으면 헤드라인 감소율은 더 줄어든다.**
  - 앱만 −48%, 앱 + 컴포지터 −32%(−31.8%), 커널 스레드 포함 **−21%**(짝지은 범위 −17 ~ −29%)다.
  - 방향("표시를 켜고도 기준보다 호스트 CPU가 낮다")은 3회 모두 유지된다.
- **표시 경로가 더하는 호스트 CPU**는 `disp_off` → `disp_asap`에서 +1.39 ms/f다(파이프라인 합 기준). 구성은 앱 +0.74, 컴포지터 +0.48, 커널 스레드 +0.18이다.
- 남는 비계수 몫은 idle 중 hardirq 시간이다(커널 설정상 계수 불가). 인터럽트는 표시 시 프레임당 약 126회이고, 대부분 IPI와 타이머다.

## 4. 주의·결정

- "무관한 사용자 프로세스"를 빼는 판단은 프로세스 이름 기준이다. 에이전트 CLI·작업 관리자·패널·샘플러 자신이 여기에 들어간다.
- idle 기준선 열(`idle_sched_ms_per_s`)과 `sys_net_ms_per_frame`은 백그라운드 흔들림 때문에 쓰지 않는다. 다음 측정에서는 백그라운드를 줄이는 편이 낫다.
- 결정: 시스템 전체(커널 스레드 포함) CPU를 같은 회차에서 재고, 파이프라인 몫(앱 + 컴포지터 + 커널 스레드)으로 정리한다 (사용자 결정, 2026-10-16).
  - 논문 반영 방식은 미결이다.

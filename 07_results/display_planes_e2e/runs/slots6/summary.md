## 3. 결론

1. **슬롯 대기가 사라졌다.** 세 설정 모두 slot wait 0이고, 평면 경로는 실제로 5장을 쥔다(held_frames_max 5). fps 도 29.87~29.90 으로 회복했다(s4 29.23~29.33).
   e2e(디코드 → NPU 완료)는 세 설정 모두 약 80 ms 로 같아졌다(s4 평면 107~108).
2. **디코드 → 화면 지연은 세 경로가 같다.** 평균 101.4 / 102.3 / 101.6 ms, p90 115.4 / 115.1 / 112.8 ms 로 차이가 평균 1 ms·p90 3 ms 이내이고 실행 간 범위가 거의 겹친다.
   **평면 경로의 지연 이득은 없다.** b2/s4 의 "평면이 약 28 ms 느림"은 슬롯 부족 탓이었고, 슬롯을 늘리면 사라진다.
   - 중앙값은 비교에 쓰지 않는다. 표시 시각이 vblank(16.7 ms) 단위로 끊겨 분포가 몇 값에 몰리므로, 중앙값이 회차마다 수 ms씩 튄다(kms 101.80~107.81, 평균은 101.18~101.78).
   - glass 끝점은 여전히 다르다(평면: 하드웨어 표시 시각, Vulkan: `vkWaitForPresentKHR` 폴링으로 알아챈 시각). Vulkan 쪽은 폴링 지연만큼 늦게 찍히므로 실제 표시는 약간 더 이를 수 있다(추정, 이 측정으로 검증하지 않음).
3. **CPU·V3D 이득은 s4 와 같다.** CPU 2.189 → 1.747 / 1.759 ms/f(**−0.44 ms, −20%**, 범위 비중첩), V3D 10.22 → 2.86 / 2.83 ms/f(**−72%**, TFU 3.74 ms 소멸).
   labwc CPU 는 Vulkan 합성과 wayland-planes 가 같다(0.611).
4. **운용점**: 표시 on 에서 평면 경로를 쓰려면 **b2/s6** 이 필요하다(s4 는 슬롯 부족). Vulkan 합성은 s4·s6 모두 슬롯 대기가 없다.
5. **늦은 프레임은 그대로다**(약 25~27%, present p90 50 ms). 슬롯과 무관하다는 것이 정식 측정으로도 확인됐다 — 원인은 상위 실험 §5-3 의 남은 일이다.

## 4. 주의

- 앱 CPU 가 s4 회차보다 높다(vk 2.059 → 2.189, wlp 1.569 → 1.747, kms 1.576 → 1.759). 슬롯이 늘어 동시에 도는 일이 늘었는지,
  세션 간 차이인지는 이 측정으로 가르지 않는다. **회차 안의 비교(평면 대 Vulkan)만 쓴다.**
- 1회 300프레임 확인 실행(fd9f7ff 검증)의 값과 `11_logs/2026-10-08_slotprobe_*` 는 비정식이다. 인용하지 않는다.

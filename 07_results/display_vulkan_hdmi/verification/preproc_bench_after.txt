## 조정자(메인) 독립 재검증 — 2026-09-20, NPU 경합의 영향

에이전트 보고(median 2.116 x3)를 재현하려 했을 때 **후처리 트랙이 NPU를 돌리는 중이었고**
그 상태의 측정은 게이트를 벗어났다. 경합이 끝난 뒤 다시 재서 통과를 확인했다.

| 상태 | gpu shader median | min / max | 판정 |
|---|---|---|---|
| 골든 (변경 전, 조용한 상태) | 2.116 / 2.116 / 2.120 ms | 2.005 / 2.561 | 기준 |
| 변경 후, **NPU 동시 실행 중** | 2.203 / 2.207 ms | 1.756 / 4.312 | 게이트 [2.074, 2.162] **이탈** |
| 변경 후, 조용한 상태 | **2.140 / 2.139 / 2.134 ms** | 2.001 / 2.588 | **통과** |

환경(조용한 상태 측정 시): SoC 64.2 C, ARM 2.4 GHz, Hailo 칩 60.8 C, /dev/hailo0 미사용.

### 결론
1. **`VulkanContext` present 옵션화에 성능 회귀는 없다.** 2.134~2.140 ms 는 게이트 안이다.
   골든 대비 +1% 는 측정 시점 온도 차이 수준이고 게이트 +-2% 안이다.
2. **NPU 트래픽이 GPU 셰이더 시간을 약 3% 늘린다**(2.14 -> 2.20 ms). 편차 폭이 훨씬 커진다
   (max 2.59 -> 4.31 ms). BCM2712 에서 V3D 와 Hailo PCIe DMA 가 메모리 대역폭을 공유하기 때문이다.
   - 이것은 새 발견이 아니라 **이미 알려진 값과 정합한다**: 전체 파이프라인에서 GPU 평균이
     2.67 ms / p90 5.57 ms 였다(`07_results/pipeline_ffmpeg_vulkan_hailo/results.csv` nhcw_b8).
     단독 실행 2.13 ms 와의 차이가 바로 이 경합이다.
   - **측정 프로토콜 주의: GPU 단독 벤치(`yvo_preproc_bench`)는 NPU 가 유휴일 때만 재야 한다.**
     `.claude/skills/measure/SKILL.md` 는 칩 냉각은 다루지만 이 항목은 다루지 않는다.
     GPU 벤치와 NPU 벤치를 병렬로 돌리면 양쪽 수치가 모두 오염된다.
3. 게이트 여유가 얇다(2.140 vs 상한 2.162). 이후 표시 경로가 추가되면 이 벤치는 표시를 끈 상태로
   재야 하고, 상한을 넘으면 먼저 경합·온도를 의심한 뒤 코드를 본다.

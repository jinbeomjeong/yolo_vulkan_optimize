2. 세 구현이 각각 빠뜨렸던 것 → 새 API가 채운 것
════════════════════════════════════════════════════════════════════════════════

                        DmaBufReadMap   HeapOutPool    DmaHeapBuffers   DmaHeapPool(신규)
  할당                  안 함(남의 fd)  HEAP_ALLOC     HEAP_ALLOC       HEAP_ALLOC
  heap 선택             –               system 고정    cached→system    설정(기본 cached→system)
  sync 방향             READ만          READ만         WRITE만          READ/WRITE/RW 전부
  sync ioctl 오류       무시            무시           검사             검사 (strict 기본, 끌 수 있음)
  DMA_HEAP_ALLOC 오류   –               검사           검사             검사
  크기 정렬             –               align_up 16384 없음             align_up(req+headroom, align)
  주소 정렬             –               검사 후 throw  없음             예약 후 MAP_FIXED 재매핑
  zero_init             –               sync 없는 memset(결함) 없음     WRITE sync 로 감싼 memset
  DMA_BUF_SET_NAME      –               없음           있음             있음
  device_headroom       –               없음           없음             있음(B.12)

주소 정렬 방식 (B.11 "throw 대신"):
  1) mmap(NULL, len+align, PROT_NONE, MAP_PRIVATE|MAP_ANONYMOUS|MAP_NORESERVE)  ← 주소 공간 예약
  2) mmap(aligned_addr, len, PROT_READ|PROT_WRITE, MAP_SHARED|MAP_FIXED, fd, 0) ← dma-buf 덮어쓰기
  3) 앞(lead)·뒤(tail) 잉여 munmap.  lead+tail == align 이므로 munmap 짝이 정확히 맞는다
  dma-buf 안의 오프셋은 **언제나 0** 이다 — HailoRT read_async 에 오프셋 인자가 없다는 §4.1 제약을 깨지 않는다.
  이 기기는 페이지 크기가 16384 라 lead 는 항상 0 이고 tail 은 항상 16384 다. 4 KB 페이지 커널에서도 맞다.

B.6(c) 결함 수정 (HeapOutPool::acquire 의 sync 없는 memset):
  DmaHeapPool::allocate() 가 zero_init 을 DmaCpuAccess(fd, Write) 로 감싸고 finish() 로 END 를 명시 검사한다.
  HeapOutPool 이 DmaHeapPool 어댑터가 되면서 **자동으로 고쳐졌다.**

common/dmabuf_map.hpp  DmaBufReadMap
  · 남긴다(남의 fd 를 읽기 전용 매핑하는 별개 용도). 공개 API·동작 불변.
  · 내부 ioctl 두 곳만 dma_sync_begin/end(fd, DmaSyncDir::Read, strict=false) 로 교체.
    strict=false 라 기존의 "실패 무시" 동작이 그대로다.
  · 사용처 6곳(test_preproc, test_detections, test_isp_preproc, preproc_bench, isp_bench,
    display_probe) 전부 무수정. ctest 39/39 유지로 확인.

hailo/tools/p2_out_buffers.hpp  HeapOutPool
  · yvo::DmaHeapPool 위의 얇은 어댑터(약 30줄). OutBufPool/OutBufRef 인터페이스 그대로.
  · "프로브 전용, yvo_hailo 에 넣지 않는다 — 링크 격리" 머리말 유지.
  · sync_cpu_read_begin/end 는 yvo::dma_sync_begin/end 로 위임. **strict=true 로 강화**(기존은 반환값 폐기).
  · device_headroom = 0 (이 버퍼는 HailoRT 로만 가고 Vulkan import 하지 않는다).
  · 링크 격리 확인: p2_out_buffers.hpp 가 include 하는 것은 common/dma_heap_alloc.hpp(헤더 전용,
    Vulkan 심볼 0) + vulkan/dmabuf_export.hpp(VulkanOutPool 용, 원래부터 있었다).
    yvo_hailo 라이브러리 자체(hailo_runner.cpp)는 이 헤더를 쓰지 않는다 — 변화 없음.

isp/dma_heap_buffer.{hpp,cpp}
  · **한 글자도 건드리지 않았다**(다른 세션 소유).
  · dma_heap_alloc.hpp 머리말에 "isp/dma_heap_buffer.hpp 가 같은 일을 한다. 소유 세션과 조율된 뒤
    어댑터로 흡수한다"와, 조율 때 넘길 것(16384 정렬 미확인, begin/end_cpu_read 부재)을 명시했다.
  · 반대 방향 주석은 남의 파일이라 달지 않았다.

vulkan/dmabuf_import.{hpp,cpp}
  · get(fd, size) → get(fd, size, min_range = 0). min_range > 0 이면 range < min_range 에 예외.
    캐시 적중 경로에서도 검사한다. 기존 2인자 호출자는 그대로 동작한다(기본값 0 = 검사 안 함).
  · :139-143 dedicated 분기는 **건드리지 않았다**(P0 가 보고한 잠재 결함. V3D 는 그 분기를 타지 않는다).

# argmax 지름길 종단간 확인 — mot20_05 실영상

`gpu_nms_e2e` 실험의 회차다. 커밋 `c0e0810`(argmax 지름길)이 `yolo_decode.comp`의 ⑤ emit을 바꿨다.
픽스처에서는 다중집합 비교로 검출 불변을 증명했지만(`postproc_stage_cost/runs/emit_shortcut/`)
**실영상 종단간 경로의 회귀 확인**이 남아 있었다. 이 회차가 그것을 닫는다.

## 1. 측정 조건

- 날짜 2026-10-11. git `71c1266`(지름길 `c0e0810` 포함)
- Raspberry Pi 5 / BCM2712 + Hailo-8 (PCIe Gen3 x1), V3D 1150 MHz, 디코더 1스레드, 표시 off
- 입력 `04_data/videos/mot20_05_h265.mp4` — 1080p25 **900프레임**, 혼잡 야간 광장(MOT20-05).
  가장 혼잡하고 지름길 이득이 최대인 입력이라 골랐다(픽스처 pass1 −36.3%)
- `06_tools/bench/nms_bench.sh`를 **수정 없이** `VIDEO=`·`OUT_DIR=`만 바꿔 돌렸다(`nms_crowd_stress` 선례).
  `MODE=verify`(3실행) 뒤 `MODE=perf`(b2s4·b8s16 × `--nms cpu|gpu`, 900프레임 × 3회 인터리브)
- 냉각: Hailo 칩 65 °C 게이트, 매 실행 전. 실행 직전 칩 온도 최대 65.0 °C
- 전체 로그 [`evidence/console.log`](evidence/console.log), 환경 [`env_bench.txt`](env_bench.txt)·`env/env_verify.txt`

### 무엇과 비교하는가

**기준선은 같은 영상·같은 설정의 변경 전 기록이다** — `07_results/nms_crowd_stress/runs/mot20_05/`
(측정 당시 HEAD `2bacfeb`, 그 결과를 기록한 커밋 `fb83f79`, 2026-10-08, 지름길 이전 — 두 커밋 사이
`01_src`·`02_shaders` 변경은 없다). 같은 V3D 1150 MHz 조건이다.

⚠ `MODE=verify`의 `[A2] PASS`만으로는 **회귀가 없다는 증거가 되지 않는다.** verify는 한 바이너리 안에서
GPU 억제 대 CPU 억제를 비교하는데, **양쪽이 같은 `yolo_decode.comp`가 디코딩한 같은 후보를 받는다.**
지름길이 후보를 망가뜨려도 둘이 똑같이 틀려 `nms_verify_mismatch`가 0으로 남는다
(`nms_crowd_stress/summary.md`가 기록한 "verify도 같은 잘린 후보끼리 비교한다"와 같은 구조).
게다가 PASS 판정식(`nms_bench.sh:367`)에는 `detections.jsonl` 비교가 들어 있지 않다.
그래서 **기준선과의 교차 커밋 대조를 따로 했다** — 그것이 이 회차의 본론이다.

기준선의 `samples/{cpu,gpu,verify}_b2s4/detections.jsonl`과 새 결과를 **정렬 후 바이트 비교**했다.

## 3. 성능 — 변경 전 대 후 (run 중앙값, 괄호는 3회 최소~최대)

| 설정 | V3D CSD ms/f | GPU 후처리 ms | FPS | e2e ms | CPU ms/f |
|---|---|---|---|---|---|
| b2s4 cpu | 2.546 → **2.256 (−11.4%)** | 0.838 → **0.548 (−34.6%)** | 34.97 → 34.98 | 141.3 → 141.3 | 0.976 → 0.955 |
| b2s4 gpu | 2.709 → **2.420 (−10.7%)** | 0.841 → **0.554 (−34.2%)** | 34.96 → 34.97 | 141.4 → 141.3 | 0.905 → 0.933 |
| b8s16 cpu | 2.588 → **2.302 (−11.0%)** | 0.881 → **0.598 (−32.1%)** | 51.49 → 51.50 | 325.9 → 326.2 | 1.018 → 0.986 |
| b8s16 gpu | 2.751 → **2.469 (−10.3%)** | 0.887 → **0.595 (−32.9%)** | 51.49 → 51.50 | 325.7 → 325.9 | 0.958 → 0.918 |

V3D CSD와 GPU 후처리는 **네 설정 모두 범위가 겹치지 않는다**(예: b2s4 gpu CSD 2.707~2.713 → 2.419~2.420).
CSD 잡 수는 4·5 jobs/f로 그대로다 — 디스패치 수는 같고 빨라졌을 뿐이다.

## 4. 결론

1. **회귀 없음.** 실영상 900프레임에서 검출이 지름길 이전과 **바이트 동일**하다(교차 커밋 대조 3쌍 identical).
2. **이 변경의 성과는 V3D 컴퓨트 예산이다 — 프레임당 약 0.29 ms(−10~11%).** V3D CSD 절감(0.290 / 0.289 /
   0.286 / 0.282 ms/f)이 GPU 후처리 절감(0.290 / 0.287 / 0.283 / 0.292 ms)과 **같다** — ⑤에서 벌어온
   시간이 그대로 GPU 여유로 나타났다. 혼잡 장면에서 표시 경로(합성·오버레이)와 V3D를 나눠 쓸 여유가 그만큼 늘었다.
3. **FPS와 지연은 바뀌지 않는다.** FPS는 NPU가(34.97 / 51.50), 지연은 슬롯이 정한다(141.3 / 325.9 ms).
   **이 변경의 이득을 FPS로 주장하지 않는다.**
4. CPU ms/f는 −4.2 ~ +3.1%로 섞여 있고 범위가 겹친다. **변화 없음으로 읽는다** — 지름길은 GPU 안의 일이다.

## 5. 주의 · 남은 일

- **신뢰 불가 값 없음.** perf 12회 전부 `runs_ok 3/3`, `unreliable 0`, `hailort_warnings 0`, `all_ok 1`.
- ⚠ **성능 비교는 교차 세션이다**(같은 바이너리 안의 라운드 교차가 아니다). 기준선과 이 회차는 같은 V3D 1150 MHz,
  같은 스크립트·설정·입력이지만 측정일이 다르다. 그래도 V3D CSD·GPU 후처리는 **범위가 겹치지 않고** 네 설정에서
  같은 방향·같은 크기라 결론을 뒤집을 만한 잡음은 아니다. 같은 바이너리 안의 직접 측정은
  `postproc_stage_cost/runs/emit_shortcut/`(`Full − legacy`)이 맡는다.
- **mot20_05 하나만 돌렸다**(사용자 결정, 2026-10-11). mot20_02(기준 21361)와 기본 영상(기준 9457)은
  재지 않았다. 지름길·폴백 분기를 가장 많이 밟는 입력이 mot20_05라 대표로 골랐다.
- 이 영상의 NMS 폴백(후보 > 1024)은 0이다(최대 267) — 이 회차가 보는 것은 디코딩 ⑤의 지름길/폴백이고
  NMS 폴백 경로는 밟지 않는다. 기준선도 같다.

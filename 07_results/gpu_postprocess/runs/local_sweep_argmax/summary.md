# local size 재스윕 — argmax 지름길 뒤에도 10×6이 맞는가

`gpu_postprocess` 실험의 회차다. 이 실험이 2026-09에 `yolo_decode.comp`의 local size를 **10×6**으로
골랐다([`evidence/p3_sweep.txt`](../../evidence/p3_sweep.txt)). 그 뒤 argmax 지름길(커밋 `c0e0810`)이
① 루프 본체를 QPU **35 → 45 명령(+10)**으로 늘렸다. 최적점이 옮겨졌는지를 확인한다.

## 1. 측정 조건

- 날짜 2026-10-11. git `71c1266`(지름길 `c0e0810` 포함)
- Raspberry Pi 5 / BCM2712, 커널 6.18.50+rpt-rpi-2712. **NPU는 쓰지 않는다**(`run_sweep`은 픽스처만 읽는다)
- V3D (Mesa 26.2.2), `v3d_freq=1150`, 부트로더 `1accd665`
- `yvo_postproc_probe --probe sweep --perf-frames 300 --warmup 30`, slots 5(기본)/10(혼잡)
- 입력: `04_data/raw_tensors`(5프레임) · `build/out/crowd_fixtures/mot20_{02,05}`(각 10프레임). 점수 0.2 고정
- **독립 프로세스 3회** × 입력 3종. `run_sweep`은 프로세스 안에서 3라운드를 교차하지만 표본을 하나로
  풀링하므로, run 수준 산포를 얻으려고 프로세스를 3번 돌렸다. 표는 **run 중앙값의 중앙값**
- 드라이버 [`evidence/run_local_sweep.sh`](evidence/run_local_sweep.sh), 환경 [`env_bench.txt`](env_bench.txt)
- 온도 69.2~74.1 °C. 75 °C 냉각 게이트는 한 번도 발동하지 않았다

### ⚠ 이전 스윕과 절대 ms를 나란히 놓지 않는다

이전 스윕은 **V3D 960 MHz · 120프레임 · 지름길 이전 셰이더**다. 클럭·프레임 수·셰이더가 동시에 다르므로
**비교할 수 있는 것은 조합 간 순위와 상대비뿐이다.** 판정도 같은 실행 안의 상대비로 했다.

### 판정 규칙 — 측정 전에 정했다

어떤 조합이 **10×6을 3% 이상** 이기고 **독립 3회 모두 같은 방향**이면 기본값을 바꾼다.
그 이하는 어깨가 평평한 것이니 invocation이 적은 현상태를 유지한다(사용자 결정, 2026-10-11).
이전 스윕에서도 1위 10×12와 10×6의 차이가 0.6%뿐이었다.

## 2. 표 — pass 1 GPU 시간 상위 4 (ms, run 중앙값)

| 입력 | 1위 | 2위 | 3위 | 4위 | **10×6 순위** |
|---|---|---|---|---|---|
| 기본 | 10×12 0.4322 | **10×6 0.4335** | 12×5 0.4400 | 5×12 0.4426 | **2/26** |
| mot20_02 | 10×12 0.5007 | **10×6 0.5018** | 10×24 0.5142 | 5×12 0.5377 | **2/26** |
| mot20_05 | 5×12 0.5083 | 10×12 0.5152 | 10×24 0.5161 | **10×6 0.5187** | **4/26** |

### 10×6 대비 상대비 (run 1 / 2 / 3, 음수 = 10×6보다 빠름)

| 입력 | 10×12 | 5×12 | 12×5 |
|---|---|---|---|
| 기본 | −0.0 / −0.3 / +0.0 % | +2.3 / +2.1 / +1.9 % | +2.4 / +1.3 / +1.1 % |
| mot20_02 | −0.2 / +0.2 / +0.1 % | +7.2 / +7.6 / +8.2 % | +7.7 / +8.6 / +8.5 % |
| mot20_05 | −0.7 / −0.8 / −0.5 % | **−2.1 / −1.8 / −2.0 %** | +8.3 / +8.2 / +8.3 % |

전체 26조합 × 9실행은 `evidence/sweep_<입력>_run{1,2,3}.txt`.

## 3. 결론

1. **10×6을 유지한다**(결정: 기본값 변경하지 않음, 사용자 결정 규칙 적용, 2026-10-11).
   3% 기준을 넘는 조합이 없다. 가장 가까운 것은 mot20_05의 5×12로, 3회 모두 같은 방향이지만 **−1.8~−2.1%**다.
2. 5×12로 바꾸면 **잃는 쪽이 더 크다** — mot20_05에서 2%를 얻는 대신 기본에서 +1.9~2.3%,
   mot20_02에서 **+7.2~8.2%** 느려진다. 10×12는 세 입력 모두 10×6과 ±0.8% 안에서 동률이다.
3. **최적점은 옮겨지지 않았다.** 순위 구조 — 10×12와 10×6이 선두이고 그다음이 12×5·5×12 — 가
   2026-09 스윕과 같다. ①에 +10 명령이 붙었어도 ①이 지연 바운드라 local size의 지형이 바뀌지 않은 것으로 읽힌다(추정).

## 4. 주의 · 남은 일

- **정확성 안전망 통과.** `--probe sweep`에는 PASS/FAIL 판정도 검증 레이어도 없다(`--validation`이
  sweep에는 적용되지 않는다 — 출력의 `[validation] errors=0`은 공허한 줄이다). 유일한 안전망은
  **`cand/frame` 열이 26행 전부 같은지**인데, 9개 파일 모두 한 값이다(기본 25 · mot20_02 206 · mot20_05 127).
  local size에 따라 후보 수가 흔들리는 버그(SWAR·패킹의 local-size 의존)는 없다.
  정확성 자체는 `postproc_stage_cost/runs/emit_shortcut/`의 다중집합 비교가 증명한다.
- 이 회차의 절대 ms(기본 10×6 0.4335)는 `emit_shortcut`의 `Full`(0.4301)과 조금 다르다 —
  `--perf-frames`(300 대 500)와 측정 도구가 다르다. **회차 간 절대값을 섞어 인용하지 않는다.**
- `--probe sweep`은 세 디스패치(P3/P4/P5)를 한 덩어리로 잰다. 스케일별 최적 local size가 다를 수
  있지만 이 도구로는 분해할 수 없다.
- 드라이버가 저장소 루트에서 프로브를 실행해 루트에 0바이트 `hailort.log`가 남았다(NPU를 열지 않아도
  `libhailort`를 로드하며 CWD에 쓴다). 지웠다. 다음 드라이버는 `11_logs/<날짜>_<무엇>/`를 CWD로 삼는 편이 낫다.

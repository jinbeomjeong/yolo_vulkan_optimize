# CPU 읽기 패턴별 대역폭 — 비캐시 V3D 메모리 (2026-10-16)

상위 실험 [`gpu_postprocess`](../../summary.md)의 P2 ⑥(할당처별 순차 `memcpy` 읽기)에 **접근 패턴**을 더한 회차다.

## 측정 배경

논문 §6.3은 NHWC→NHCW 런타임 변환이 V3D 메모리를 "1바이트씩 stride 3으로 읽는" 비용을 0.088 GB/s로 적었다.
그런데 이 값은 잰 것이 아니라, 변환이 차지한 약 14 ms를 1,228,800 B로 나눈 역산값이었다.
논문 심사(2026-10-16, paper-reviewer 5차 M1)가 이를 순환 논증으로 지적했다.

결정: 문구를 낮추기 전에 stride 마이크로벤치를 먼저 잰다 (사용자 결정, 2026-10-16).

## 1. 측정 조건

- 날짜: 2026-10-16 11:34~11:45 (KST)
- 하드웨어: Raspberry Pi Compute Module 5 Rev 1.0, kernel 6.18.50, Mesa 26.2.2
  - V3D 1150 MHz, ARM 2400 MHz, governor ondemand
  - NPU·표시 미사용
- 코드: 커밋 `bc87e17`(`yvo_postproc_probe --probe stride`). 바이너리 md5는 [`env_bench.txt`](env_bench.txt)에 있다.
  - 측정 시점에는 작업 트리에 문서 변경(논문 원고)만 있었다.
- 명령: `yvo_postproc_probe --probe stride --rounds 3 --repeats 10 --cpu 3`을 독립 실행 3회 돌렸다.
  - 셀당 30표본이고 워밍업은 3이다.
  - 패턴 × 할당처를 표본마다 인터리브하고, 할당처 순서를 돌린다.
  - CPU는 코어 3에 고정했다.
  - 이어서 같은 세션에서 `--probe gpuab`를 1회 돌렸다.
- 버퍼: 1,228,800 B. NPU 입력과 같은 640×640×3 NHWC uint8이다.
- 할당처 3종:
  - V3D `HOST_VISIBLE|HOST_COHERENT` 매핑. V3D의 유일한 메모리 타입(`0x7`)이고 `HOST_CACHED`가 없다.
  - malloc
  - 캐시 dma-heap 매핑. Vulkan에 import해 장치 attachment를 붙였고, `DMA_BUF_IOCTL_SYNC` START·END를 측정 구간에 포함했다.
- 패턴 4종. 모두 malloc 목적지에 쓴다.
  1. 순차 `memcpy`
  2. 1바이트 순차 스칼라 루프
  3. 1바이트 stride-3 전치(실제 NHWC→NHCW 루프)
     - 스칼라로 컴파일됐는지 `objdump`로 확인했다: `ldrb …,#3` / `strb`, 벡터 명령 0개.
  4. 같은 전치를 자동 벡터화로 컴파일한 것
     - NEON `ld3`가 생긴다. 원본을 채널마다 다시 읽으므로 load 기준으로는 원본을 3번 읽는다.
- 결과 검증: 표본마다 목적지 체크섬을 CPU 기준과 대조했다. 3회 모두 불일치 0이고 `[RESULT] stride PASS`다.
- 냉각:
  - 실행 전마다 SoC 62 °C를 목표로 최대 120 s 기다렸다. 상온 때문에 목표에 닿지 않았다.
  - 실행 시작 온도는 63.7~67.0 °C였다.
  - `throttled=0xe0000`은 부팅 이후 누적 비트이고, 현재 비트(0~3)는 0이다.

## 3. 결론

- **역산값은 직접 측정과 맞는다.** 스칼라 stride-3 전치의 V3D 실효 대역폭은 0.097 GB/s(12.69 ms)다.
  - 논문의 역산값 0.088 GB/s(약 14 ms)와 10% 안이다.
  - 같은 전치가 malloc에서는 0.95 ms, V3D에서는 12.7 ms(13.4배)다. 따라서 "전치 연산이 아니라 메모리 읽기가 비싸다"는 주장은 직접 측정으로 성립한다.
- **비용을 정하는 것은 stride가 아니라 읽기 단위다.**
  - V3D에서 1바이트 **순차** 읽기(12.82 ms)와 stride-3 읽기(12.69 ms)는 같다.
  - 같은 메모리를 넓은 load로 순차 복사하면(`memcpy`) 0.78 ms로 16배 빠르다.
  - 비캐시 매핑에서는 1바이트 load 하나하나가 메모리까지 가서(약 10 ns/B) 접근 순서와 무관하게 비싸다(**해석**, 매핑 PTE 속성은 보지 않았다).
  - 컴파일러가 `ld3`로 벡터화해도 1.55배만 빨라진다(8.17 ms).
  - 반면 malloc과 heap에서는 바이트 읽기도 1 ms 안팎이다.
- 따라서 논문 §4.3.2·§6.3의 "stride 3 접근이 최악의 패턴"이라는 서술은 "비캐시 메모리를 바이트 단위로 읽는 것"으로 고쳐야 한다.
  - 설계 지침은 그대로다: GPU가 쓴 버퍼는 GPU·DMA가 소비하고, CPU가 꼭 읽어야 하면 넓은 순차 복사로 한 번에 가져온다.

## 4. 주의

- malloc 행은 낙관적 기준이다. 원본이 표본 사이에 캐시에 남는다. 할당처 비교에는 V3D 대 heap을 함께 본다.
- HailoRT 런타임 변환 함수(`libhailort` `0x1c10cc` 부근, 심볼 없음)의 실제 루프는 이 프로브의 스칼라 루프와 같다고 확인하지 않았다.
  - 프로브 12.7 ms와 파이프라인에서 사라진 약 14 ms의 차이(약 1.4 ms)는 그 루프 차이나 파이프라인 안의 경합일 수 있다.
- 실행 디렉터리의 `hailort.log`는 0 B(NPU 미사용)이고, `11_logs/2026-10-16_stride_read/`에 남겼다.

## 5. 정정 (2026-10-16, integrity-auditor 대조 뒤 추가 — 위 본문은 고치지 않는다)

- §4 "약 14 ms의 차이(약 1.4 ms)"는 **약 1.3 ms**가 맞다. 14 − 12.69 = 1.31이고, 역산 기준(1,228,800 B / 0.088 GB/s = 13.96 ms)으로는 1.27이다.
- §2.1 "V3D 행이 0.5% 이내"는 **약 0.5%**가 맞다. V3D `memcpy`의 3회 범위가 0.51%(0.782~0.786)이고, 나머지 V3D 셀은 0.07% 이하다.
- §3 "10% 안"은 기준에 따라 다르다. 대역폭 기준(0.088 대비)은 **+10.2%**, 시간 기준(약 14 ms 대비)은 −9.4%다.
- §1 냉각의 "목표 62 °C, 최대 120 s"와 "시작 온도 63.7~67.0 °C"는 측정 스크립트의 콘솔 출력(대화 기록)에서 온 값이다. 이 폴더에는 근거 파일이 없다.
  - 폴더 안의 근거는 `evidence/stride_run*.txt`의 `[env]` 64.2·65.9·65.9 °C(실행 시작)와 `env_bench.txt`의 66.4(전)·67.0(후) °C다.

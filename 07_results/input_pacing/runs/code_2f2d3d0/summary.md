# 입력 페이싱 재측정 — 메인 스레드 이벤트 대기 코드(`2f2d3d0`) (2026-10-16, 표시 off)

모 실험 [`../../summary.md`](../../summary.md)(2026-10-12)와 같은 벤치·설정 12개·집계로 다시 쟀다.
목적은 커밋 `2f2d3d0`에서 최저 지연 운용점(O2) 수치가 유지되는지 확인하는 것이다.
이 커밋은 입력 페이싱의 "다음 도착까지 대기" 루프를 500 µs sleep에서 이벤트 대기(`SlotExchange::wait_event_until`)로 바꿨다.

## 1. 측정 조건

- 날짜: 2026-10-16 03:25~04:09 (KST). 하드웨어는 Raspberry Pi 5, Hailo-8, PCIe **Gen3 x1**, V3D 1150 MHz다.
- 소프트웨어: kernel 6.18.50, HailoRT 4.24.0, mesa 26.2.2. 전부 [`env_bench.txt`](env_bench.txt)에 있다.
- 코드: 커밋 **`2f2d3d0`**. 바이너리 md5 `3dda5b0f…`는 [`../../../display_e2e/runs/v3d1150_20261016`](../../../display_e2e/runs/v3d1150_20261016/summary.md)과 같다.
  그 사이 커밋 `78ae8c8`은 주석만 바꿔 재빌드 결과가 바이트 단위로 같다.
- 명령: `RUNS=3 FRAMES=900 OUT_DIR=07_results/input_pacing/runs/code_2f2d3d0 bash 06_tools/bench/input_pace_bench.sh`. 콘솔 전문은 [`raw/_session/bench_stdout.log`](raw/_session/bench_stdout.log)다.
- 조건은 모 실험과 같다.
  - dmabuf, NHCW, GPU 후처리, GPU NMS, 표시 off, 디코더 1스레드
  - 도착 900프레임 × 3회. 실행 순서는 run 바깥, 설정 안쪽이다.
- 신뢰성
  - 36회 모두 `hailort.log`의 warning 0, error 0이다.
  - 냉각은 17회(75 °C 초과 시)였고, 칩 최고 온도는 80.8 °C다.

## 3. 결론

- **O2(b1/s1 + 페이싱 + 큐 1)는 그대로다.** 도착 기준 평균 58.36 ms(모 실험 58.33), 버림 18.6%다.
  p90은 1 ms 줄었다(72.66 → 71.71).
- **30 fps를 따라가는 b2 설정은 조금 짧아졌다.** 평균은 −0.6~−1.0 ms, p90은 −4.2~−4.6 ms(104.1~104.5 → 99.9~100.0)다.
  변경 전에는 다음 도착까지 500 µs씩 끊어 자고 NPU 완료를 그 주기로 확인했다. 지금은 완료 이벤트로 바로 깨어 결과를 마무리한다.
  꼬리(p90)가 줄어든 것은 그 지연이 사라진 것과 맞는다(**추정**, 원인을 따로 가르지 않았다).
- 결론 구조는 모 실험과 같다.
  - N은 b2에서 효과가 없다(큐 최대 깊이 1).
  - b1/s1에서는 N이 한 단계 늘 때마다 약 +33 ms다.
  - 처리 fps와 버림은 같다.

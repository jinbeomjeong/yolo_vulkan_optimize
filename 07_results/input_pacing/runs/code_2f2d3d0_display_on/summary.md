모 회차 [`../display_on`](../display_on/summary.md)(2026-10-12)와 같은 벤치·설정 5개·집계로 다시 쟀다(`DISPLAY_RUN=1 FRAME_LOG=1`).

- 이전: `display->pump()`를 위해 500 µs씩 sleep했다.
- 이후: 같은 상한 안에서 NPU 완료 이벤트(`SlotExchange::wake`)나 GPU 후처리 완료로 일찍 끝난다.

## 3. 결론

- **O2(Vulkan 합성, b1/s1)가 좋아졌다.** 처리가 23.31에서 24.24 fps로 올라 표시 off(24.42)와 거의 같아졌고, 버림은 22.2%에서 19.1%가 됐다.
  도착 → 화면은 평균 70.2 ms, p90 78.6 ms로 각각 −2.9 ms, −4.0 ms다.
  - 모 회차는 처리 주기가 늘어난 원인을 "슬롯이 표시 변환 펜스까지 기다린 뒤 돌아온다"로 봤다. 이번에는 처리 주기(1000/처리 fps)가 표시 off 40.95 → 표시 on 41.25 ms로 0.3 ms만 는다(모 회차는 같은 정의로 40.97 → 42.90 ms, +1.9 ms. 모 회차 summary의 40.92 → 42.31 ms는 frame_log NPU 완료 간격 중앙값이라 정의가 다르다).
  - 펜스 확인이 500 µs sleep 간격에 묶여 있던 몫이 이벤트 대기로 줄었다고 본다(**추정**).
  - 표시가 더하는 지연(표시 off `e2e_arr` 58.36 대비)은 약 12 ms다. 모 회차에서는 약 15 ms였다.
- **HVS 평면 경로의 b1은 오히려 늘었다.** `dwlp_b1s2`는 +5.0 ms, `dwlp_b1s3`는 +8.4 ms이고, 처리 fps와 버림은 같다.
  원인은 가르지 않았다. 늘어난 것은 도착 기준 e2e(추론 완료까지)도 같다(56.9 → 57.4, 80.2 → 87.6 ms).
- **b2는 경로와 무관하게 같다**(±2 ms). 평면 경로가 꼬리가 짧은 성질(최대 125 대 189 ms, p90 108.7 대 123.4 ms)도 그대로다.
- 배치 1에서 평면 경로가 지연과 처리량을 함께 이기는 설정이 없다는 모 회차의 결론은 이번에 더 뚜렷해졌다.
  O2 표시 on의 권고 구성(Vulkan 합성)도 그대로다.

## 4. 주의

- 늦은 프레임(`late_frames`)과 그림 7(`fig07_arrival_to_present`)용 `frame_log.csv`는 이 폴더 `raw/dvk_*_run*/`에 있다.
- HVS 평면 b1의 증가는 원인을 확인하지 않은 관찰이다. 평면 경로의 b1 구성은 권고하지 않으므로 운용 결론에는 영향이 없다.
- 결정: O2 표시 on 수치를 이 회차 값(도착 → 화면 평균 70.2 ms, 버림 19.1%)으로 갱신한다 (사용자 결정, 2026-10-16).

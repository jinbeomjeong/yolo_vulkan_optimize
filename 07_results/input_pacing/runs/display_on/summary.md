# 입력 페이싱 + 표시 on — 도착 → 화면(arrival-to-present)

`input_pacing` 실험의 회차다. 본 폴더의 페이싱 측정은 표시 off 였다(`e2e_arr` = 도착 → NPU 완료). 커밋 `11040f3` 이
`--input-pace source` 와 `--display on` 을 함께 쓸 수 있게 하고 **도착 → 화면** 지표(`arrival-to-present`, `RESULT_CSV5`, `--frame-log` 의 `present_ms`)를
더했으므로, 같은 페이싱(큐 1)에 표시를 켜서 **표시가 무엇을 더하는지**를 쟀다. 질문은 셋이다.
(1) 최소 지연 운용점 O2(b1/s1)의 도착 → 화면은 얼마인가, (2) 표시를 켜면 O2 의 버림률이 왜 오르나(스모크 22% 대 표시 off 18.6%),
(3) HVS 평면 경로(`wayland-planes`)는 b1 에서 slots 2·3 중 무엇을 내주나(평면 + slots 1 은 교착).

### 2.3 설정별 해석

- **O2 Vulkan(`dvk_b1s1`)**: 처리 주기가 40.92 → **42.31 ms**(+1.4 ms)로 늘어 처리 23.31 FPS, 버림 1 − 23.31/30 = **22.2%**(표시 off 18.6%).
  slots 1 에서는 슬롯이 **후처리와 표시가 모두 끝나야**(Vulkan 합성은 표시 제출 fence) 돌아온다. 후처리 완료 뒤 다음 제출까지의 틈이
  표시 off 약 0 ms 에서 약 4.3 ms(= 42.31 − 34.47 − 3.48)로 생겼고, 이는 V3D 표시 변환(`display_convert.comp` 3.62 ms) + 오버레이(0.11 ms) + fence 대기다.
  같은 기간 제출 → NPU 완료가 3.1 ms 줄어(NPU 지연 35.2 → 31.1 ms) 일부를 상쇄해서 순증가는 1.4 ms 다.
  **도착 → 화면 평균 73.1 ms, p90 82.6 ms** — 표시 off `e2e_arr`(58.3) 대비 약 +15 ms, 그중 표시 구간이 평균 16.9 ms(변환 3.6 + vblank·FIFO·labwc 합성 대기)다.
- **평면 b1/s2(`dwlp_b1s2`)**: 처리 주기가 정확히 **50.00 ms = 60 Hz vblank 3개**에 잠겨 19.98 FPS, 버림 **1/3**. 평면 스캔아웃은 화면에 떠 있는 버퍼를
  다음 프레임이 vblank 에 걸릴 때까지 쥐므로, slots 2 에서는 한 슬롯이 늘 화면에 묶이고 다음 프레임 처리는 이전 프레임이 vblank 에 걸린 뒤에야 시작된다.
  처리 약 41 ms 가 다음 vblank 로 올림되어 50 ms 가 된다. 대신 표시 구간이 가장 짧아(11.9 ms, p90 13.6 — V3D 변환 없음) **`a2p` 평균 68.4 ms 로 다섯 설정 중 가장 낮다.**
- **평면 b1/s3(`dwlp_b1s3`)**: 슬롯 하나를 더 주면 vblank 잠김이 풀려 처리 주기가 표시 off 와 같은 40.92 ms(24.37 FPS, 버림 18.4%)가 된다.
  대신 NPU 에 두 프레임이 들어가 뒤 프레임이 앞 프레임의 추론을 기다린다 — 제출 → NPU 완료가 34 → **67 ms**(NPU 지연 64.6 ms).
  큐 대기는 14.5 → 8.5 ms 로 줄지만 순 **`e2e_arr` +23 ms, `a2p` 평균 90.8 ms**(p90 101.8). → **s2 = 낮은 지연·20 fps, s3 = 24.4 fps·지연 +22 ms** 의 교환이다.
- **b2(`dvk_b2s4`·`dwlp_b2s6`)**: 처리는 표시와 무관하다 — `e2e_arr`(82.7·81.7)·처리 주기·버림 0 이 표시 off(81.5)와 같다.
  표시가 **평균 약 21 ms**(Vulkan 20.7, 평면 21.8)를 더해 **`a2p` 평균 103.3·104.1 ms** 다. b1 보다 표시 구간이 긴 것은 batch 2 의 짝이 약 2 ms 간격으로 함께 끝나는데
  화면에는 따로 올라가야 하므로 짝의 둘째가 기다리기 때문이다(짝의 둘째: `e2e_arr` 중앙값 72.7 → `a2p` 103.9 ms, Vulkan).
  - Vulkan(FIFO)은 짝을 **연속 vblank(1v, 16.7 ms)** 에 올리고 그다음 약 67 ms 를 쉰다(표시 간격 중앙값 17.1, p90 67.0 ms) — 30 fps 가 고르게 보이지 않는다.
  - 평면은 표시 간격 중앙값 **33.3 ms**(p90 50.0)로 소스 박자에 더 가깝고 꼬리가 짧다(`a2p` p90 113.3 대 119.0, max 129.6 대 185.3 ms).

## 3. 결론

1. **O2(b1/s1, Vulkan 합성)의 도착 → 화면은 평균 73.1 ms, p90 82.6 ms, 최대 약 97 ms** 다(버림 22.2%). 표시 off `e2e_arr` 58.3 ms 대비 표시가 **약 15 ms** 를 더한다.
2. **표시를 켜면 O2 의 버림이 18.6 → 22.2% 로 오르는 원인은 slots 1 의 슬롯 반납이 표시 완료를 기다리기 때문**이다.
   V3D 표시 변환(3.6 ms) + fence 대기가 처리 주기에 직렬로 들어가 주기가 40.9 → 42.3 ms 로 늘었다(처리 24.41 → 23.31 FPS). 스모크(22.3%)와 같다.
3. **HVS 평면 경로 b1 은 slots 에서 지연과 처리량을 맞바꾼다.** s2 는 `a2p` 평균 **68.4 ms**(최저)지만 처리 주기가 vblank 3개(50 ms)에 잠겨 **20 fps(버림 33%)**,
   s3 은 24.4 fps(버림 18.4%)지만 NPU 에 두 프레임이 겹쳐 `a2p` **90.8 ms** 다. s1 은 교착(기존 동작)이라 쓸 수 없다.
   O2 Vulkan(73.1 ms, 23.3 fps)은 그 사이에 있다 — 평면 경로가 b1 에서 **지연과 처리량을 동시에 이기는 설정은 없다.**
4. **30 fps 를 다 처리하는 b2 에서는 표시가 처리에 영향을 주지 않고 도착 → 화면이 약 103~104 ms** 다(표시 구간 약 21 ms — 짝의 둘째가 화면 차례를 기다리는 몫).
   평균은 Vulkan·평면이 같고, 평면이 **p90·max 꼬리가 짧고 표시 간격이 고르다**(33.3 ms 대 Vulkan 의 17/67 ms 교대).

## 4. 주의·남은 일

- **NPU 지연이 표시 on b1 에서 4 ms 짧다**(35.2 → 31.1 ms). 표시 off O2 는 NPU 가 끝나자마자 다음 프레임이 제출되고, 표시 on 은 4~17 ms 의 틈 뒤에 제출된다.
  연속 제출에서 HailoRT/PCIe 쪽에 무엇이 겹치는지는 **확인하지 않았다**(원인 미확인). O2 표시 on 의 `e2e_arr`(56.1)이 표시 off(58.1)보다 짧은 것은 이 때문이다.
- `dvk_b1s1` 의 GPU 전처리 셰이더 시간(RESULT_CSV `gpu_ms_mean`)이 **0.19 ms(중앙값 0.006 ms)** 로 나왔다(평면 b1·Vulkan b2/s4·표시 off 는 1.7~1.8 ms). 전처리가 실제로 그렇게
  짧을 수 없으므로 **timestamp 측정의 왜곡**으로 본다(V3DV timestamp 는 CPU 큐 잡이다). Vulkan 합성 + b1/s1 에서만 나타났고 원인은 가르지 않았다. 이 표에는 쓰지 않았다.
- `a2p` 는 **도착 예정 시각**(t0 + k/30 s) 기준이다. 실제 카메라라면 노출·ISP 지연이 더해진다. "화면에 닿은 시각"을 Vulkan 합성과 평면 경로가 같은 방식으로
  얻는지는 이 회차에서 확인하지 않았고, 패널 자체의 입력 지연은 포함하지 않는다.
- late frames 는 평면 경로만 판정된다(Vulkan 은 vblank 순번이 없어 nan). b2 Vulkan 의 1v/4v 교대는 late frames 로 잡히지 않고 표시 간격 분포로만 보인다.
- 페이싱 행의 `cpu_ms_per_frame`(표시 on 1.6~1.9 ms)은 처리 프레임당 값이고 labwc 의 CPU 는 들어 있지 않다 — 표시 off 페이싱(1.0~1.1)과의 차이를 표시 비용으로 읽지 않는다.
- 칩 온도: 실행 중 최고 80.4 °C(냉각 게이트 사이 30 s 실행). 연속 운용(thermal_soak) 조건이 아니다.
- 측정하지 않은 것: 평면 b1/s2 의 vblank 잠김을 피하는 다른 방법, kms 백엔드(이번 범위 밖), 표시 on 에서 큐 N ≥ 2, 다른 주사율.
- 결정: 아직 없다. 표시 on 최소 지연 운용점을 무엇으로 둘지(O2 Vulkan 73 ms·23 fps 대 평면 s2 68 ms·20 fps)는 사용자가 정한다.

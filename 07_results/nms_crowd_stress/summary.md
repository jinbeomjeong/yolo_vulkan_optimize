# 혼잡 장면 스트레스 시험 — GPU 디코딩·NMS 후처리

후처리(`yolo_decode.comp` → `efficient_nms.comp`, 판정할 수 없는 프레임만 CPU)의 **혼잡할 때만 드러나는 경계**를 실제 혼잡 영상과
점수 임계값 스윕으로 지나 본다. 기존 입력(`video_h265.mp4`)은 후보가 프레임당 평균 16.8·최대 45개라 이 구간을 지난 적이 없다
([`gpu_nms_e2e/`](../gpu_nms_e2e/summary.md)). 이번 범위는 **측정과 판정**이다 — 코드는 바꾸지 않았다.

| 경계 | 동작 | 시험 전 우려 |
|---|---|---|
| 후보 > 1024 (`kMaxSelected`) | GPU NMS를 포기하고 그 프레임을 CPU greedy로 처리 | CPU greedy는 O(n²) — 메인 스레드가 멈출 수 있다 |
| 후보 > 4096 (`max_dets`) | 디코딩 버퍼가 넘치면 `read_candidates()`가 **앞 4096개만** 읽는다 (`01_src/vulkan/yolo_postproc.cpp:644`) | 후보가 조용히 버려지고, verify도 같은 잘린 후보끼리 비교한다 |
| 클래스당 100개 (HEF 설정) | 초과분을 버린다(HailoRT도 같다) | 사람이 많으면 실제 검출 손실 |
| IoU 보호대 | 판정이 애매한 쌍이 있으면 그 프레임을 CPU로 | 겹치는 박스가 많을수록 빈도 증가 |

- 1024을 넘은 프레임은 **설계대로 전부 CPU로 처리됐다**(보호대 0). CPU 억제 비용은 n ≈ 1000~1900에서 **프레임당 약 0.8~1.5 ms(최대 2.8 ms)**다.
  같은 클래스의 살아 있는 후보끼리만 비교하므로 O(n²)의 최악보다 훨씬 싸다. 시험 전 "수~수십 ms" 우려는 틀렸다.

## 3. 결론

1. **실제 혼잡 장면에서 후처리는 정확하고 싸다.** 후보가 기존 영상의 약 11배(180~183개)여도 FPS는 그대로이고, 검출은 CPU·GPU 경로가 바이트 단위로 같으며,
   CPU로 넘긴 프레임은 없었다. GPU NMS는 0.05 → 0.18 ms, pass1은 0.55 → 0.77~0.89 ms, V3D CSD는 +0.4~0.5 ms/f 늘었다.
2. **GPU NMS의 CPU 이득이 혼잡에서 드러나기 시작한다.** CPU 억제 원가가 2 µs → 40~47 µs/f로 커져, 같은 세션의 cpu 대 gpu 중앙값이
   −0.02~−0.07 ms/f로 gpu 쪽이 낮다(단 실행 간 범위는 일부 겹친다).
3. **1024 경계의 CPU 처리는 안전한 비상구다** — 프레임당 약 0.8~1.5 ms(최대 2.8 ms), 처리량 영향 없음. 다만 점수 0.2에서는 혼잡 장면에서도 닿지 않았다(최대 267).
4. **4096 경계의 잘림은 잠재 결함이다.** 지금 조건으로는 양자화 바닥에서도 최대 1925개라 도달할 수 없지만, 다른 HEF(클래스·앵커가 많은 모델)나 더 혼잡한 장면에서 넘치면
   검출을 조용히 잃고 verify도 못 잡는다.
5. **혼잡 장면의 실제 한계는 후처리가 아니라 검출 재현율**이다(주석 밀도 73~227명 대 검출 21~26명). 클래스당 100 한도와 IoU 보호대는 한 번도 작동하지 않았다.

## 4. 주의·남은 일

- **고칠 후보(사용자 결정)** — 4096 넘침 시: (a) 넘친 프레임은 원시 텐서에서 CPU 전체 디코딩(`cpu_yolov8_postprocess`)으로 처리,
  (b) `max_dets` 상향(32 B × n, 슬롯당 128 KB → n=16384면 512 KB), (c) 최소한 넘친 프레임을 결과에 표시해 조용한 손실을 없앤다. 넘침을 잡는 verify 기준도 함께 필요하다.
- 이 실험의 표시 on(b2s4 + 표시) 혼잡 부하는 재지 않았다. V3D가 표시 변환과 나눠 쓰므로 GPU 예산 증가(+0.4~0.5 ms/f)의 영향은 표시 경로에서 따로 봐야 한다.
- 2.3절의 점수 0.05 이하는 검출 의미가 달라지는 **부하 생성용** 설정이다. 그 검출 수를 정확도 지표로 쓰지 않는다.
- 2.2절 기존 영상 행은 다른 세션 값이다. 세션 간 CPU는 비교하지 않는다(같은 세션의 cpu 대 gpu만 본다).
- 사람 재현율을 높이는 일(입력 해상도·모델)은 이 실험의 범위 밖이다.

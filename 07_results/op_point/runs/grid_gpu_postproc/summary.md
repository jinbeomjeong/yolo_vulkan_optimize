## 3. 해석

### 3.1 FPS = min(배치 천장, 슬롯 제약)

| batch B | 배치 천장 실측 (slots = 2B) | `B / T(B)`, T(B) = 24.8 + 16.2·B ms | 차이 |
|---:|---:|---:|---:|
| 1 | 24.42 (`b1/s2`) | 24.39 | +0.1% |
| 2 | 34.99 (`b2/s4`) | 34.97 | +0.1% |
| 4 | 44.48 (`b4/s8`) | 44.64 | −0.4% |
| 8 | 51.50 (`b8/s16`) | 51.81 | −0.6% |

- **slots ≥ 2B이면 FPS가 배치 천장에 닿는다.** 그 천장은 NPU 단독 배치 모델 `B / T(B)`([`latency_gen3_cooled`](../latency_gen3_cooled/summary.md))와 0.6% 안에서 맞는다.
  2B를 넘는 slots는 FPS를 올리지 못하고 지연만 늘린다(`b1/s2→s8`, `b2/s4→s8`).
- **slots < 2B이면 슬롯이 제약이다.** 같은 비율 slots/B에서 주기에 일정한 몫이 더해진다(실측에서 맞춘 관계, 원인은 확인하지 않았다).

| slots / B | 설정 | 배치 주기 실측 ms (= B / FPS) | T(B) ms | 초과 ms |
|---:|---|---:|---:|---:|
| 1 | `b2/s2` · `b4/s4` · `b8/s8` | 81.9 · 114.5 · 177.5 | 57.2 · 89.6 · 154.4 | **24.7 · 24.9 · 23.1** |
| 1.5 | `b2/s3` · `b4/s6` · `b8/s12` | 65.5 · 98.1 · 159.6 | 57.2 · 89.6 · 154.4 | **8.3 · 8.5 · 5.2** |
| 2 | `b2/s4` · `b4/s8` · `b8/s16` | 57.2 · 89.9 · 155.3 | 57.2 · 89.6 · 154.4 | 0.0 · 0.3 · 0.9 |

  slots = B이면 배치 하나가 돌아오기 전에 다음 배치를 채울 수 없다. 그래서 배치마다 약 24 ms가 겹치지 못하고 드러난다.
  이 값은 T(B)의 고정항 24.8 ms와 크기가 같지만, 같은 것인지는 확인하지 않았다(추정).
- 그 결과 **slots = B인 설정은 batch를 반으로 줄이고 slots = 2B로 둔 설정과 FPS가 같다.**
  `b2/s2` = `b1/s2`(24.42), `b4/s4` ≈ `b2/s4`(34.92 / 34.99), `b8/s8` ≈ `b4/s8`(45.07 / 44.48).

### 3.2 지연 ≈ slots × 프레임 주기

batch 1은 FPS가 24.42로 고정이라 slots 효과만 드러난다. NPU 지연이 34.5 → 75.4 → 157.0 → 319.6 ms로
**slots(1·2·4·8) × 프레임 주기 41 ms**를 따른다(첫 칸은 큐 대기가 없다). 상위 실험 §4.1의 관계가 그대로 다시 확인된다.

### 3.3 파레토 전선 (FPS ↑, e2e mean ↓)

| 설정 | FPS | e2e mean / p90 ms | 쓰임 |
|---|---:|---:|---|
| `b1/s1` | 24.42 | 79.2 / 81.9 | 최소 지연 (30 fps 미달) |
| `b2/s3` | 30.53 | 128.0 / 152.5 | 30 fps 경계 (+1.8%) |
| **`b2/s4`** | **34.99** | **139.6 / 166.7** | **30 fps 실시간, 여유 +16.6%** |
| `b4/s6` | 40.77 | 167.9 / 212.0 | |
| `b8/s8` | 45.07 | 195.5 / 253.1 | |
| `b8/s12` | 50.11 | 252.8 / 272.1 | 최대의 97%를 지연 −69 ms로 |
| `b8/s16` | 51.50 | 321.8 / 432.4 | 최대 처리량 |

전선 밖(같은 FPS에서 지연이 더 길다): `b1/s2·s4·s8`, `b2/s2`, `b2/s6·s8`, `b4/s4`(`b2/s4`보다 p90이 16.6 ms 길다), `b4/s8`.
`b8/s8`은 `b4/s8`보다 FPS +1.3%, e2e −2.5 ms로 근소하게 앞선다. FPS 범위가 겹치지 않지만 차이는 작다.

## 4. 2026-09-20 측정(`--postproc host`, V3D 960 MHz)과의 비교

| 설정 | FPS 이전 → 지금 | e2e mean 이전 → 지금 ms | CPU ms/f 이전 → 지금 |
|---|---|---|---|
| `b2/s2` | 24.41 → 24.42 | 122.46 → 120.05 | 3.299 → 0.947 |
| `b2/s4` | 34.97 → 34.99 | 142.17 → 139.60 | 3.289 → 0.894 |
| `b4/s4` | **33.42 → 34.92 (+4.5%)** | 142.81 → 139.94 | 3.440 → 0.927 |
| `b8/s8` | 44.55 → 45.07 (+1.2%) | 199.05 → 195.50 | 3.251 → 0.915 |
| `b4/s8` | 44.44 → 44.48 | 199.58 → 198.04 | 3.271 → 0.946 |
| `b8/s16` | 51.49 → 51.50 | 325.26 → 321.82 | 3.428 → 0.850 |

- 처리량 천장은 변하지 않았다. 병목은 여전히 NPU/PCIe다.
- CPU는 3.3 → 0.85~1.0 ms/f로 줄었다. GPU 후처리 덕분이다(상위 실험 §5.6과 같은 방향).
- e2e는 2~4 ms 짧아졌다. GPU 전처리가 2.1~3.0 → 1.81 ms로 빨라진 몫(V3D 1150 MHz)과 크기가 맞다.
- `b4/s4`만 +4.5% 달라졌다. 이전에는 이 설정만 GPU 시간이 4.87 ms로 튀었는데(상위 §6, 원인 미확인), 지금은 1.81 ms로 다른 설정과 같다.
  이전 값은 그 이상 현상에 눌린 것으로 보인다(추정).
- `b1/s1`의 이전 값(81.59 ms)은 `--gpu-depth 1`·600프레임 조건이라 직접 비교하지 않는다. 참고로 지금은 79.2 ms다.

## 5. 결론

1. **운용점 권고는 바뀌지 않는다.** 30 fps 실시간은 `b2/s4`(34.99 FPS, e2e 139.6 ms), 최대 처리량은 `b8/s16`(51.50 FPS), 최소 지연은 `b1/s1`(79.2 ms)이다.
2. **"slots만 보면 된다"는 상위 실험의 요약은 반쪽이다.** FPS는 batch가 정하는 천장 `B / T(B)`와 slots 제약 중 작은 쪽이다.
   천장에 닿으려면 **slots = 2B**가 필요하고, 그보다 크면 지연만 는다. 상위 §4.3이 T(B) 모델이 틀린다고 든 예(`b4/s4` 예측 44.5 대 실측 33.4)는 slots = B인 슬롯 제약 구간이었다.
3. **새 중간 운용점 `b8/s12`**: 50.11 FPS(최대의 97%)를 e2e 252.8 ms(p90 272.1)에 낸다. `b8/s16`보다 평균 69 ms, p90 160 ms 짧다.
4. CPU는 모든 설정에서 0.85~1.0 ms/f다. 운용점 선택이 CPU를 바꾸지 않는다.

## 6. 주의 · 남은 일

- 표시 off에서만 쟀다. 표시 on에서는 `slots + gpu_depth` 제약과 평면 경로의 버퍼 보유(평면 경로는 s6 필요)가 붙는다. 이 표의 FPS·지연을 그대로 옮기지 않는다.
- 3.1절의 "slots = B일 때 약 24 ms 초과"는 세 점에서 맞춘 관계일 뿐이다. 원인(설정 재적재가 겹치지 못하는지, 호스트 재충전 시간인지)은 확인하지 않았다.
- 칩 온도는 실행 끝에 최대 82 °C까지 올랐지만 경고는 0건이다.
- slots 상한(8 / 16)은 HEF 스트림 큐 깊이에서 온다. 상위 실험의 `b2/s8` 기술과 맞는다.

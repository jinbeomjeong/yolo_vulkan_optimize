# argmax 지름길 — ⑤의 클래스 재스캔을 없앤다

`postproc_stage_cost` 실험의 회차다. 앞 회차 [`emit_split`](../emit_split/summary.md)이 **⑤ 비용의
94.4~97.8%가 클래스 재스캔**이고 atomic 몫은 0이라는 것, 그리고 **앵커당 후보가 "정확히 1개"가 100.00%**
라는 것을 밝혔다. 즉 재스캔은 "①이 이미 본 그 1개 클래스를 다시 찾기 위해 80 word를 재순회하는 일"이었다.
이 회차는 ①에서 그 클래스를 들고 나오는 변경의 **순효과**를 잰다.

## 1. 측정 조건

- 날짜 2026-10-11. git `e0112b7` + 미커밋 지름길 구현
- Raspberry Pi 5 / BCM2712, 커널 6.18.50+rpt-rpi-2712. PCIe 8.0 GT/s x1 — **NPU는 쓰지 않는다**
- V3D 7.1.10.2 (Mesa 26.2.2), `v3d_freq=1150`, 부트로더 `1accd665`
- 입력: `04_data/raw_tensors`(5프레임) · `build/out/crowd_fixtures/mot20_{02,05}`(각 10프레임)
- `--probe stages --perf-frames 500 --warmup 50 --rounds 3`, local 10×6, slots 5/10. **검증 레이어는 끈다**
- **독립 프로세스 3회** × 회차 안 변형 3라운드 교차. 표는 **run 중앙값**
- 드라이버 [`evidence/run_emit_shortcut.sh`](evidence/run_emit_shortcut.sh), 환경 [`env_bench.txt`](env_bench.txt)

### 무엇을 무엇과 비교하는가 — 커밋 간 비교가 아니다

`legacy`는 **변경 전 ①+⑤를 같은 소스에서 `YVO_DECODE_LEGACY_EMIT`로 컴파일한 빌드**다. 그래서
`Full − legacy`는 **한 바이너리 안에서 같은 라운드 교차로 재는 직접 측정**이고, 커밋 간 비교가 아니다.

기준선이 진짜 기준선임을 두 가지로 확인했다.
- `yolo_decode_stop1_legacy.spv`의 md5 `dc7f9de14434c6835a2097bad9f1c92f`가 **앞 회차의 `stop1.spv`와 바이트 동일**하다
  (`emit_split/env_bench.txt` 참조). ① 기준선이 변경 전과 같은 바이너리다.
- `legacy` 빌드의 SPIR-V는 변경 전 셰이더와 **SSA id 번호만 다르고 명령열 715줄이 같다**(`spirv-dis` 후 id 정규화 diff).

⚠ **`S1`·`S2`·`S3`는 이제 새 ① 위에서 빌드된다.** 앞 회차의 단계 수치와 **직접 비교하면 안 된다**.
변경 전 ①의 값이 필요하면 이 표의 `stop1_legacy`를 쓴다.

## 2. 표 — pass 1 GPU 시간 (ms, run 중앙값)

| 입력 · thr | `legacy` | `Full` | **순효과** | 범위 | **Δ①** | ⑤ 잔여 |
|---|---:|---:|---:|---|---:|---:|
| 기본 · 0.2 | 0.4999 | 0.4301 | **−0.0698 (−14.0%)** | 비중첩 | +0.0394 | 0.0399 |
| mot20_02 · 0.2 | 0.7445 | 0.5010 | **−0.2435 (−32.7%)** | 비중첩 | +0.0392 | 0.0507 |
| mot20_05 · 0.2 | 0.8091 | 0.5151 | **−0.2940 (−36.3%)** | 비중첩 | +0.0395 | 0.0518 |
| mot20_05 · 0.02 | 1.1636 | 0.6694 | **−0.4942 (−42.5%)** | 비중첩 | +0.0392 | 0.1393 |
| mot20_05 · 0.003 | 1.6885 | 1.7402 | **+0.0517 (+3.1%) 회귀** | 비중첩 | +0.0396 | 1.0904 |

Δ① = `S1 − stop1_legacy`(①의 증가분). ⑤ 잔여 = `Full − S3`.
"범위"는 run 3회의 최소~최대가 두 빌드 사이에서 겹치는지다 — **다섯 조건 모두 겹치지 않는다**
(마지막 행은 회귀 방향으로 겹치지 않는다). 원시값 90개는 `evidence/stages_*_run{1,2,3}.txt`에 있다.

⑤는 앞 회차에서 0.1263 / 0.3103 / 0.3671 / 0.6596 / 1.0660이었다. thr 0.2 세 입력에서
**0.0399 / 0.0507 / 0.0518로 줄었다**(68~86% 감소). thr 0.003은 1.0660 → 1.0904로 사실상 그대로다.

## 3. 결론

1. **운용 임계값(0.2)에서 pass1이 14.0~36.3% 줄었다.** 혼잡 장면에서 더 크다 — 재스캔이 후보 수에
   비례했기 때문이다. 범위가 겹치지 않는다.
2. **Δ①은 다섯 조건에서 +0.0392~+0.0396 ms로 일정하다**(①② 0.302 → 0.341, +13%). ①의 추가 비용이
   후보 수와 무관한 고정비라는 설계 예측과 맞는다. QPU 명령은 반복당 35 → 45(+10)다.
   이 비용은 지름길이 ⑤에서 벌어오는 0.11~0.33 ms에 견줘 작다.
3. **thr 0.003에서는 이득이 0이고 Δ①만 남아 +0.05 ms 회귀한다.** 구조적이다 — 그 조건의
   `q_thr_low`가 **0**이라 정수 프리필터가 아무것도 걸러내지 않고, 모든 앵커가 폴백으로 간다.
   0.02·0.003은 후보를 늘려 부하를 만드는 설정이고 운용점이 아니다(모 회차 §1).
4. **최종 검출은 바뀌지 않는다.** 15회 실행 전부 `Full` 대 `legacy`의
   `anchor_key → (score 비트, class_id, 좌표 비트)` 다중집합이 **불일치 0건**이다
   (후보 115 / 2019 / 1686 / 9927 / 15823). 순열 흡수에 기대지 않고 **다중집합이 같다.**

## 4. 주의 · 남은 일

- **신뢰 불가 값 없음.** 15회 전부 `[RESULT] stages PASS`·`[multiset] PASS`, 검증 레이어 `errors=0`,
  V3D 1150 MHz 고정, 69.2~73.6 °C(모 회차 71.9~74.1 °C·앞 회차 71.4~74.7 °C와 같은 대역),
  `throttled=0xe0000`은 부팅 후 **이력** 비트만. NPU를 열지 않아 `hailort.log`는 0바이트로 남지 않는다.
- ⚠ **수용 기준을 측정 중에 바로잡았다.** 원래 "Δ①② ≤ +0.03 ms"를 걸었는데 그것은 **대리 지표**이고,
  Δ①이 +0.039로 그 선을 넘으면서도 순효과는 이득이다. ① 증가는 설계가 의도적으로 치르는 비용이라
  상한으로 묶으면 순이득이 나는 변경을 기각한다. `legacy`가 같은 바이너리 안의 기준선이므로
  **판정은 순효과로** 했다(thr 0.2 세 입력 전부 `Full < legacy`, 범위 비중첩). Δ①은 진단 수치로 남긴다.
- ⚠ **저임계값 회귀는 고치지 않았다.** `q_thr_low = 0`이면 지름길이 한 번도 걸리지 않는다.
  운용 임계값이 0.2라서 지금은 문제가 아니지만, 임계값을 0.02 아래로 내릴 일이 생기면 재검토해야 한다.
- ⚠ `q_thr_low > 128`인 HEF(SWAR 클램프 경로)는 이 데이터에 없어 **실측하지 못했다.** 클램프가
  과대 추정 방향으로만 틀려 폴백으로 보낼 뿐이라는 논증으로만 커버된다(셰이더 주석).
- 정적 지표: `spills:fills = 0:0` 유지, `threads` 2 → 2(절단 빌드는 4 → 4). 레지스터 압박으로
  측정이 왜곡될 여지는 없다. 원시 덤프는 `11_logs/2026-10-11_argmax_shortcut/shaderdb_raw.txt`(git 밖).
- ⚠ **이득을 FPS로 주장하면 안 된다.** `nms_crowd_stress` §2.2-2.3에서 혼잡·저임계값에서도 FPS는
  51.46~51.50으로 불변이었다. 이 비용의 의미는 V3D CSD 예산(2.47~2.75 ms/f)의 여유다.
- local size 재스윕(`--probe sweep`)은 **하지 않았다.** ①의 명령 수가 늘어 10×6 최적점이 옮겨졌을 수 있다.
- 파이프라인 종단간 A/B(`nms_bench.sh MODE=verify`)는 **하지 않았다.** 픽스처 다중집합 일치로
  검출 불변을 증명했지만 실영상 경로의 회귀 확인은 남아 있다.

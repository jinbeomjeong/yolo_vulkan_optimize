# emit 분리 측정 — ⑤의 비용을 재스캔 몫과 atomic 몫으로 쪼갠다

`postproc_stage_cost` 실험의 회차다. 모(母) 회차가 ⑤ emit을 pass1의 26~63%로 재고 "atomic을 워크그룹
단위로 모으기"와 "클래스 비트마스크"를 제안으로 남겼는데, **둘 중 어느 쪽이 실제 비용인지는 재지 않았다**
(모 `summary.md` §4). 이 회차가 그 질문에만 답한다.

## 1. 측정 조건

- 날짜 2026-10-11. git `f3535cd` + 미커밋 계측(진단 변형 2개 + `--probe stages --variants` + `--probe groups`)
- Raspberry Pi 5 / BCM2712, 커널 6.18.50+rpt-rpi-2712. PCIe 8.0 GT/s x1 — **NPU는 쓰지 않는다**
- V3D 7.1.10.2 (Mesa 26.2.2), `v3d_freq=1150`, 부트로더 `1accd665`
- 입력: `04_data/raw_tensors`(5프레임) · `build/out/crowd_fixtures/mot20_{02,05}`(각 10프레임)
- `--probe stages --perf-frames 500 --warmup 50 --rounds 3`, local 10×6, slots 5(기본)/10(혼잡)
- **독립 프로세스 3회**(반복이 바깥 루프, 조건이 안쪽 루프) × 회차 안 변형 3라운드 교차. 표는 **run 중앙값**
- 드라이버 [`evidence/run_emit_split.sh`](evidence/run_emit_split.sh), 환경 [`env_bench.txt`](env_bench.txt)

**모 회차와 같은 조건이라 수치를 직접 비교할 수 있다.** 모 회차 로그의 온도는 71.9~74.1 °C였고 이 회차는
71.4~74.7 °C다(같은 열 대역). 생산 셰이더 SPIR-V md5 `2bb79b8b700b9a2eca7925183a9fbe1b`와
`yolo_decode_stop{1,2,3}.spv` md5가 **모 회차와 동일** — 계측 추가가 기존 경로를 건드리지 않았다는 증거다.

### 변형 (진단 전용, 결과가 틀려도 된다)

| 변형 | 무엇을 뺐나 | 남긴 것 |

## 3. 결론

1. **⑤의 비용은 사실상 전부 클래스 재스캔이다 — 94.4~97.8%.** 모 회차가 남긴 두 제안 중
   "atomic을 워크그룹 단위로 모으기"는 **지렛대가 아니다.**
2. **atomic 몫은 0이다.** −0.0080 ~ +0.0024 ms로 부호조차 일정하지 않다(측정 잡음).
   ⑤가 대역폭이 아니라 지연에 묶여 있다는 것과 일관된다 — ⑤의 달성 대역폭은 0.056 GB/s로
   ①의 2.22 GB/s의 1/40이고, 반복 1회가 약 82 cycle(1150 MHz)이다.
3. **"클래스를 바깥 루프로 돌리는" 교환의 이득 상한은 ⑤ 전체가 아니다.** 그룹당 평균 통과 앵커가
   1.369~1.738뿐이라 재스캔 로드는 `1/n`로만 줄고, 상한은 재스캔 × (1 − 1/n) =
   **기본 0.033 ms · mot20_02 0.125 ms · mot20_05 0.116 ms**다(⑤의 26~41%).
   그룹당 최대 320 로드는 **최악 가정**이고 실제 평균은 약 110이다.
4. **앵커당 후보가 "정확히 1개"가 세 입력 전부 100.00%다.** 즉 재스캔은 "①이 이미 본 그 1개 클래스를
   다시 찾기 위해 80 word를 재순회하는 일"이다. ①에서 그 클래스 인덱스를 들고 나오면 재스캔 자체가
   사라진다 — 재스캔 몫 전체(기본 0.119 / 혼잡 0.294~0.355 ms)가 이론 상한이 된다.
   **이 회차는 그 설계를 측정하지 않았다**(다음 회차 몫이다).

## 4. 주의 · 남은 일

- **신뢰 불가 값 없음.** 15회 실행 전부 `[RESULT] stages PASS`, 검증 레이어 `errors=0`,
  V3D 1150 MHz 고정, `throttled=0xe0000`은 부팅 후 **이력** 비트만(현재 상태 비트 0).
  `warnings=1`은 비호환 ICD 로더 경고(`VK_ERROR_INCOMPATIBLE_DRIVER`)로 이 측정과 무관하다.
  **NPU를 열지 않으므로 `hailort.log`는 0바이트로 남아 보관하지 않았다** — 열 판정은 위 세 지표로 했다.
- ⚠ **`noatomic`은 "경합" 비용만 재고 "예약 왕복" 비용은 재지 못한다.** `idx = count; count = idx+1`도
  같은 의존 TMU 왕복을 타고 그 결과가 `dets[idx]` 주소에 필요하다. 따라서 위 "atomic 몫 ≈ 0"을
  **subgroup 집계(ballot)의 이득 상한으로 읽으면 안 된다** — ballot은 경합이 아니라 왕복 **횟수**를 줄인다.
  상한을 재려면 메모리 왕복이 전혀 없는 결정적 인덱스 변형이 따로 필요하다(미구현).
- ⚠ `norescan`은 `a` 루프가 완전 언롤되어 코드젠이 Full과 다르다(`inst` +124, `uniforms` +54, `loops` 7→5).
  재스캔 몫은 **순수한 로드 차이가 아니라 코드젠 변화가 섞인 추정치**다. 다만 측정값이 Full보다 낮게
  나왔으므로 "재스캔 지배"라는 방향은 뒤집히지 않는다.
- ⚠ **낮은 임계값은 운용점이 아니다.** thr 0.02·0.003은 후보를 늘려 부하를 만드는 설정이다(모 회차 §1).
  `q_thr_low`가 thr 0.2에서 57/53/52인데 thr 0.003에서는 **0**이라 정수 프리필터가 아무것도 걸러내지 않는다.
- ⚠ **이득을 FPS로 주장하면 안 된다.** `nms_crowd_stress` §2.2-2.3에서 혼잡·저임계값에서도 FPS는
  51.46~51.50으로 불변이었다. 이 비용의 의미는 V3D CSD 예산(2.47~2.75 ms/f)의 여유다.
- `spills:fills`는 원본·두 변형 전부 `0:0`이고 `threads`는 2로 불변이라, 레지스터 압박이 이 차분을
  왜곡하지 않았다. 차분법 자체의 한계(변형마다 레지스터 할당·스케줄이 달라 단계 비용은 근사)는
  모 회차 §4와 같다 — **0.01 ms 아래 값은 "무시할 만하다" 이상으로 읽지 않는다.**

# 지름길이 못 받는 앵커 — ⑤ 폴백(재스캔)의 빈도와 원인

`postproc_stage_cost` 실험의 회차다. 앞 회차 [`emit_shortcut`](../emit_shortcut/summary.md)은 ①에서
`pmax4`(최고 점수 + 클래스)와 `ge_cnt`(느슨한 기준 통과 개수)를 들고 나와, 통과 개수가 1이면 ⑤에서 클래스
텐서를 다시 읽지 않는 지름길을 넣었다. 개수가 2 이상이면 예전처럼 80워드를 다시 읽는다(폴백).
이 회차는 **폴백이 얼마나 자주, 왜 일어나는지**를 센다.

## 1. 조건

- 날짜 2026-10-11. git `9f3d8e5`. **GPU·NPU를 쓰지 않는다** — 원시 출력 픽스처에서 셰이더의 판정을
  파이썬으로 그대로 재현했다([`evidence/rescan_causes.py`](evidence/rescan_causes.py)). 환경 [`env_bench.txt`](env_bench.txt)
- 입력: `04_data/raw_tensors`(기본 영상 5프레임) · `build/out/crowd_fixtures/mot20_{02,05}`(각 10프레임, git 밖 —
  만든 방법은 [`nms_crowd_stress/evidence/inputs.txt`](../../../nms_crowd_stress/evidence/inputs.txt)). 픽스처 md5는 `env_bench.txt`
- 재현한 판정(`02_shaders/yolo_decode.comp`):
  - ⑤ 진입: 앵커 최고 `q ≥ q_thr_low`, `q_thr_low = ⌊thr / cls_scale⌋`
  - 지름길: `#{c : q_c ≥ t_sw} == 1`, `t_sw = min(q_thr_low, 128)` — `ge_cnt` 바이트
  - 확정 판정: float32 `(q − zp) × scale ≥ thr`
- 폴백 앵커의 원인 분류(확정 판정을 통과한 클래스 수로):
  - **2개 이상** → 실제 다중 클래스. 상위 두 클래스가 같은 묶음({car, truck, bus}, {handbag, backpack, suitcase})이면
    **원인 1(비슷한 클래스)**, 아니면 **원인 2(겹친 물체)**
  - **1개 또는 0개** → **원인 3(느슨한 정수 기준의 양자화 헛경보)**

### 지름길 한 번을 비트 단위로 ([`evidence/trace_group.txt`](evidence/trace_group.txt))

기본 영상 frame 0, P3, 행 h=47, 앵커 w=36~39(스레드 하나). thr 0.2(`q_thr_low` 57):
car(c=2) 워드 `0xd00e3204` → 앵커별 q = 4, 50, 14, 208. 끝난 뒤 `pmax4 = [0x0202, 0x1902, 0x0702, 0x6802]`,
`ge_cnt = 0x01000000`. 앵커 3은 `0x6802 >> 7 = 208`, `& 0x7f = 2`(car), 개수 1 → **지름길로 emit**(점수 0.7217).
같은 앵커들을 thr 0.02(`q_thr_low` 5)로 보면 truck(c=7, q=8, 점수 0.028)도 통과해 `ge_cnt = 0x02010100`이 되고,
앵커 3만 **폴백**(car+truck 둘 다 emit)으로 간다 — 원인 1의 실례다.

## 3. 결론

1. **운용 임계값 0.2에서 폴백은 세 입력 모두 0건이다**(⑤ 진입 3871개 전부 지름길). 0.2에서 ⑤가
   0.126 → 0.040 ms(혼잡 0.367 → 0.052 ms)로 준 것은 재스캔이 거의 통째로 사라졌기 때문이다.
2. **임계값을 낮추면 폴백의 대부분은 원인 1(비슷한 클래스 사이의 망설임)이다**(70~93%). 예외는 mot20_05 0.02로
   원인 1이 42%, 원인 2가 30%다. 원인 3(양자화 헛경보)은 0.02에서도 폴백의 많아야 약 28%다(26.1% · 18.4% · 27.7%).
3. 원인 2(겹친 물체)는 혼잡 장면의 낮은 임계값에서만 의미 있게 나온다(mot20_05 0.02에서 53건, 사람 + 소지품).

## 4. 주의

- **0건은 "드물다"이지 "불가능"이 아니다.** P1 판정(40프레임, `gpu_postprocess/evidence/p1_combination_sweep.txt`)에서는
  0.2에서 argmax만 쓰면 HailoRT NMS 검출 81개 중 1개를 놓쳤다 — 2클래스 앵커가 실재한다(`08_learn/03_yolo_tensor.md`). 그 경우 폴백이 정확히 처리한다.
- 원인 1·2의 경계는 클래스 쌍으로 나눈 **추정**이다. 텐서만으로는 실제로 물체가 둘이었는지 알 수 없다
  (handbag+backpack은 둘 다 있었을 수도 있고, motorcycle+bicycle은 묶음 밖이라 원인 2로 셌다).
- 프레임 수가 적다(5 · 10 · 10). 비율은 대략치다.
- 이 회차는 시간을 재지 않는다. 비용은 `emit_shortcut`의 측정이 정본이다.

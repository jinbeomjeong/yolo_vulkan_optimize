# 단계 혼합 잔차의 원인 (2026-11-06)

[`stage_split`](../stage_split/summary.md)에서 CPU 기준 구현의 레터박스(한 루프, 8.85 ms)가 같은 출력을 내는 분리 구현(7.33 ms)보다 약 1.5 ms 느렸다. 그 원인을 코드 변형과 하드웨어 카운터로 조사했다.

**판정: 부분 규명.** 약 1.05 ms는 메커니즘까지 확인했고, 약 0.48 ms는 크기만 확인했다.

## 측정 조건

- 날짜: 2026-11-06 00:47 시작(KST), 시간 측정은 01:13까지, 이어서 카운터·L1 실험. 환경은 [`env_bench.txt`](env_bench.txt), 실행 기록은 [`evidence/timing.log`](evidence/timing.log).
- Raspberry Pi Compute Module 5, Cortex-A76 2.4 GHz, GCC 14.2. **CPU 거버너 performance 고정**(측정 동안만, trap으로 `ondemand` 원복). NPU·표시 미사용.
- 입력 `video_h265.mp4`, 디코더 1스레드, `taskset -c 3`, 워밍업 60 + 600프레임.
- 시간: 19변형 × 5회 인터리브(95회, 모두 rc 0), 값은 레터박스 구간 중앙값. 변형별 범위 폭 0.04 ms 이하.
- 카운터: 12변형 × 2세트 × 3회(72회, 모두 rc 0), `perf_event_open` 그룹, 사용자 모드.
- 소스: [`06_tools/probes/residual_cause/`](../../../../06_tools/probes/residual_cause/). `01_src/ref/`와 기존 `--impl`은 고치지 않았다.
- 원래 git 밖 `11_logs/2026-11-06_residual_cause/`에서 실행했고, 그 결과를 이 폴더로 옮겼다. 20 MB의 `perf` 샘플은 옮기지 않았다.

## 결론

- 잔차는 전부 그림 행의 CPU 코어 실행 쪽에 있다. 패딩은 양쪽이 같고(0.19 ms), 모든 버퍼를 L1에 넣은 조건에서도 재현된다([`evidence/core.log`](evidence/core.log), 합성 입력).
- 약 1.05 ms: 패딩 판정 뒤의 부동소수 연산이 루프 밖으로 옮겨지지 않아 픽셀 루프가 147개 명령이 된다. 같은 소스를 `-fno-trapping-math`로 빌드하면 115개가 되고 출력은 같다. 그래서 트랩 의미론이 원인으로 보이나, GCC 패스 덤프로 확인하지는 않았다.
- **기각:** 레지스터 스필(핫 루프 스택 접근 0), 분기 예측 실패(0.00), 인라이닝, 벡터화, `to_u8` 클램프, Y/UV 캐시 효과, 측정 경계, 코드 정렬.
- 프레임 전체의 실제 이득은 1.5가 아니라 약 1.33 ms다. 분리 구현은 프레임 크기 float 버퍼 때문에 SAND→선형이 +0.178 ms 늘어난다.
- 전처리 절감은 기준 구현 기준 10.51 ms에서, 분리 구현 기준이면 약 9.14 ms로 약 13% 준다(wall 차이를 뺀 추정). 방향은 변하지 않는다.

## 주의·남은 일

- 명령 구성이 같아도 스케줄만 달라지면 0.39 ms가 움직인다(`ref` 8.842 대 `rowsplit` 9.231). 소스상 재적재만 뺀 `local_params`도 9.300 ms로 느려졌다. 그래서 0.48 ms에 스케줄 우연이 섞였을 가능성을 배제하지 못한다.
- 두 루프 이득의 메커니즘은 미확인이다. 비순차 실행 창 크기 가설은 시험하지 않았다(nop 추가, `-fno-schedule-insns2`가 후속 실험이다).
- 값은 이 코어·컴파일러·소스에 한정된다.
- 그림 12의 리사이즈 5.06 · YUV→RGB 2.07 · 패딩 0.19 ms는 기준 구현의 분해가 아니라 **더 빠른 분리 구현의 단계 값**이다. 10.59 ms를 스칼라 CPU의 하한으로 쓰지 않는다.
- 측정 중 `claude` 프로세스가 코어 3에 간헐적으로 올라왔다(누적 CPU 약 5%). 값의 범위가 좁아 결론은 바뀌지 않지만 격리된 측정은 아니다.
- SoC 실행 전 65.9~71.4 °C, 실행 후 최고 75.2 °C, `get_throttled` `0xe0000`(현재 비트 0). ASan은 돌리지 않았다(진단 전용 프로브).
- 소스의 `run_matrix.sh`·`run_phase2.sh`는 출력 경로가 `11_logs` 아래로 고정돼 있다. 재현할 때 그대로 쓰고 결과만 옮긴다.

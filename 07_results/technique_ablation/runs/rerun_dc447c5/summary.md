# 기법 제거 전체 재측정 — 현재 바이너리(dc447c5)

상위 [`technique_ablation`](../../summary.md)(2026-11-06)과 [`dmabuf_ablation`](../dmabuf_ablation/summary.md)은 `c97c274` 이전 바이너리(md5 ef24741c)로 쟀습니다. `c97c274`는 확정 구성(O2)의 응용 CPU를 줄였는데([`cpu_trim`](../cpu_trim/summary.md)), 특히 입력·출력 복사 경로를 직접 바꿨습니다. 그래서 논문의 구성 비교(§6.4·§7.1, 그림 12·13·15)를 같은 바이너리 값으로 다시 쓰기 위해 9개 설정을 모두 다시 쟀습니다. 결정: 기법 제거 전체를 현재 바이너리로 재측정한다 (사용자 결정, 2026-11-09).

**결론부터 적습니다.**
- 확정 구성(`base`)의 응용 CPU는 1.534 → **1.348 ms/처리 프레임**입니다(같은 날 `cpu_trim`과 같은 값).
- 기법을 하나씩 뺐을 때 늘어나는 CPU는 세 기법에서 커지고, 복사 쪽 두 구간과 전체 복사는 조금 작아집니다.
  - NHWC→NHCW 변환 +13.38 → **+13.92**
  - GPU 후처리 전체 +1.52 → **+1.76**
  - GPU→NPU dma-buf +0.74 → **+0.88**
- 복사 세 구간을 모두 CPU 복사로 바꾸면 1.348 → 3.707 ms(+2.36, 약 2.75배)입니다. 이전 회차는 1.44 → 3.80(+2.37)이었습니다.
- 처리량·지연은 이전 회차와 같습니다.

## 3. 결론

**1. 확정 구성의 응용 CPU는 1.35 ms/처리 프레임입니다.** 도착 프레임 기준으로는 1.09 ms입니다. 표시를 끄면 0.74 ms입니다.

**2. 기법별 기여의 크기 순서는 그대로입니다.** NHCW 직접 출력(+13.9) ≫ GPU 후처리(+1.8) ≈ 디코더→GPU 공유(+1.1) > GPU→NPU 공유(+0.9) > NPU→GPU 공유(+0.3)입니다. GPU NMS는 CPU를 줄이지 않습니다(−0.03, 범위가 겹침).

**3. 증가분이 바뀐 몫은 대부분 기준이 줄어든 몫입니다.** `c97c274`의 절감(사전 매핑 크기·후처리 명령 버퍼 사전 기록)은 `base`를 0.19 ms 줄였습니다.
- 비교 구성 쪽은 `post_host` +0.05, `input_copy` −0.05로 거의 같고, `layout_nhwc`만 +0.60 늘었습니다. 그래서 NHWC 변환(+0.55), 후처리(+0.23), GPU→NPU 공유(+0.14)의 증가분이 커졌습니다.
- 반대로 디코더→GPU(+1.17 → +1.13), NPU→GPU(+0.33 → +0.30), 전체 복사(+2.37 → +2.36)는 조금 작아졌습니다. 이전 값은 `base`가 1.437이던 `dmabuf_ablation` 회차라, 기준 차이(0.09 ms)보다 작은 변화입니다.
- 같은 바이너리끼리의 비교가 아니므로, 이전과 이번의 증가분 차이(±0.6 ms 이내)는 해석하지 않습니다. 이 회차 안의 값만 씁니다.

## 4. 주의·남은 일

- 비교는 이 회차 안에서만 합니다. 이전 회차의 증가분을 이 회차의 `base`에 더하지 않습니다.
- `nms_cpu`와 `base`의 범위가 겹칩니다(1.306~1.346 대 1.342~1.422). GPU NMS의 CPU 효과는 0으로 봅니다.
- `display_off` 행의 `all_ok` 0은 표시 off에서 화면 결과 줄이 없어서 생긴 표시입니다.

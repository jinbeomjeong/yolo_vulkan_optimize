# 제출을 일부러 늦추면 표시 off에서도 도착 기준 지연이 준다 — `--submit-delay-ms` 스윕

[`display_npu_window`](../display_npu_window/summary.md)(2026-11-09)는 확정 구성(O2)에서 표시를 켜면 도착 기준 지연이 4.7 ms 짧아지는 이유를 이렇게 해석했습니다.
- 장치 주기(X + G)는 같습니다.
- 표시 작업 때문에 다음 GPU 제출이 늦어지고, 그 사이 NPU가 출력 뒤 장치 작업을 마칩니다. 그래서 다음 프레임의 X(GPU 제출 → NPU 완료)가 짧아집니다.

그러나 이 해석은 파이프라인 안에서 직접 확인하지 않았습니다(paper-reviewer 지적). 그래서 표시 off에서 제출만 일부러 늦추는 진단 옵션 `--submit-delay-ms`(dc447c5, 기본 0)를 넣고 스윕했습니다. 결정: 진단 옵션으로 구현·측정한다 (사용자 결정, 2026-11-09).

**결론부터 적습니다.** 해석이 맞습니다.
- 지연 4 ms까지는 장치 주기가 40.92 ms 그대로입니다. 늘린 G만큼 X가 줄고, 도착 기준 지연 평균이 58.31 → 53.69 ms(−4.6 ms)로 표시 on 값(53.61 ms)과 같아집니다. 처리량은 24.43 → 24.41 FPS입니다.
- 6 ms부터는 장치 주기가 늘어 처리량이 떨어집니다(6 ms 24.28, 8 ms 23.99 FPS). 파이프라인 안에서 겹칠 수 있는 출력 뒤 장치 작업 시간은 약 5~6 ms입니다(단독 측정 `tail_ms` 8.35 ms보다 짧음).

## 3. 결론

**1. 표시 on의 지연 단축은 제출 시점의 효과입니다.** 표시를 끈 채 제출만 늦춰도 같은 일이 일어납니다. D = 4 ms(G 4.62 ms)에서 X 36.30 ms와 `e2e_arr` 평균 53.69 ms로, 표시 on(G 4.94, X 35.99, 53.61 ms)과 거의 같습니다. [`display_npu_window`](../display_npu_window/summary.md)의 해석(장치 주기는 같고, 늦은 제출이 NPU의 출력 뒤 장치 작업과 겹친다)을 파이프라인 안에서 직접 확인했습니다.

**2. 겹칠 수 있는 몫은 약 5~6 ms입니다.**
- D 0 → 4 ms에서는 G가 늘어난 만큼 X가 줄어 X + G가 40.92 ms로 그대로입니다(X 40.36 → 38.30 → 36.30).
- D 6 ms에서 X + G가 40.99 ms, 8 ms에서 41.50 ms로 늘어납니다. 제출이 장치 작업이 끝난 뒤까지 밀려 장치가 기다리기 시작한다는 뜻이고, 그만큼 처리량이 떨어집니다(24.28, 23.99 FPS).
- 단독 측정의 출력 뒤 장치 작업 시간(`tail_ms` 8.35 ms, [`hef_context_profile`](../../../hef_context_profile/summary.md))보다 짧습니다. 파이프라인에서는 그 일부가 이미 G = 0.57 ms 안이나 다른 단계와 겹친 것으로 봅니다(확인하지 않음).

**3. 표시 off의 최적점은 D ≈ 4 ms입니다.**
- 처리량 −0.02 FPS로 도착 기준 지연 평균이 −4.6 ms(−7.9%), p90이 −5.0 ms입니다.
- D 6 ms는 평균을 1.4 ms 더 줄이지만 처리량 −0.6%와 버림 +0.5%p를 치릅니다. D 8 ms는 중앙값이 더 줄지 않습니다. 대기 때문에 도착 → 제출이 17.2 → 19.1 ms로 늘기 때문입니다.
- 앱 CPU는 변하지 않습니다(설정별 중앙값 0.68~0.70 ms/f. 개별 실행에는 d0 0.833, d2 0.773 같은 튀는 값이 있습니다).

## 4. 주의·남은 일

- **기본값은 바꾸지 않았습니다.** `--submit-delay-ms`는 기본 0인 진단 옵션입니다. 표시 off 운용점에 D 4 ms를 쓸지는 사용자 결정 사항입니다.
- 표시 on에 D를 더하는 조합은 재지 않았습니다. 표시 on은 이미 G ≈ 4.9 ms라 더할 여지가 거의 없을 것으로 봅니다.
- 한 영상, 3회, 배치 1/슬롯 1만 쟀습니다. 최적 D는 HEF의 출력 뒤 장치 작업 시간에 달려 있으므로 모델(HEF)이 바뀌면 다시 재야 합니다.
- D 6 ms 이후 장치 주기가 늘어나는 정확한 시점(5 ms 근처)은 1 ms 간격으로 재지 않았습니다.

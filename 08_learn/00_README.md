# 08_learn — 이 프로젝트를 이해하기 위한 배경지식

이 폴더는 **배경지식이 전혀 없는 상태에서 `yolo_vulkan_optimize` 를 이해하기 위한 자습 교재**다.

## 왜 이 폴더가 있나

이 저장소에는 이미 좋은 문서가 많다 — 실행 안내([`README.md`](../README.md)),
실험 결과 12건([`07_results/`](../07_results/)), 파이프라인 다이어그램([`09_diagrams/`](../09_diagrams/)),
논문 초고([`10_paper/paper_ko.md`](../10_paper/paper_ko.md)).

그런데 그 문서들은 전부 **배경지식이 있는 독자**를 전제한다. 예를 들어 논문의 이 한 문장은
설계의 핵심을 담고 있지만,

> VStream 입력은 NHWC지만 장치 입력은 NHCW다.

읽으려면 텐서 레이아웃·양자화·PCIe·DMA·캐시 일관성을 이미 알아야 한다.
셰이더 첫 줄도 마찬가지다:

> SAND128 NV12 → letterbox RGB888 (BT.709 limited range)

**이 폴더는 그 사이를 메우는 사다리다.** 새로운 설계를 제안하지 않고,
기존 문서와 코드를 읽을 수 있게 만드는 것만 한다.

### 수치의 정본은 여기가 아니다

성능 수치의 공식 출처는 [`07_results/`](../07_results/) 의 각 `summary.md` 다.
이 폴더는 그걸 **가리키고 해설**할 뿐이라, 대표적인 몇 개만 출처 링크와 함께 인용한다.
**두 곳의 값이 다르면 `07_results/` 가 맞다.**

## 세 가지 읽기 코스

목적에 따라 읽는 순서를 다르게 잡았다.

### 코스 A — 빠른 이해 (약 2~3시간)

"이 프로젝트가 뭘 했는지 설명할 수 있으면 된다."

```
01 큰 그림  →  02 하드웨어  →  10 왜 이렇게 만들었는가
```

10장이 앞 챕터들의 개념을 짧게 다시 설명하므로 03~08을 건너뛰어도 따라갈 수 있다.
모르는 용어가 나오면 [99 용어집](99_glossary.md)을 찾는다.

### 코스 B — 코드를 고칠 사람 (약 1~2주)

"직접 만지고 측정해야 한다."

```
01 → 09 코드 지도 → 02 → 05 Vulkan → 06 zero-copy → 03 YOLO/텐서
   → 04 NPU → 07 영상·표시 → 08 방법론 → 10 설계 사슬
```

06장과 08장을 건너뛰지 마라. **이 프로젝트에서 사고가 나는 곳이 그 둘이다** —
GPU 메모리를 CPU로 읽는 설계를 무심코 넣거나, 오염된 조건에서 측정하고 결론을 내리는 것.

"[`10_paper/paper_ko.md`](../10_paper/paper_ko.md) 를 이해하고 싶다."

```
01 → 03 YOLO/텐서 → 04 NPU → 06 zero-copy → 10 설계 사슬 → 논문
```

논문 §3(배경)이 03·04·06장의 압축판이고, §4~§6이 10장의 사슬을 실험으로 뒷받침한 것이다.

## 읽기 전에 알아 둘 것

### 1. 이 프로젝트는 FPS를 올린 프로젝트가 아니다

처리량은 거의 변하지 않았다(34.96 → 34.87 FPS). **원래 그럴 예정이었다** —
병목이 NPU로 가는 PCIe 통로이고, 이 프로젝트가 건드린 것은 그 앞뒤이기 때문이다.

얻은 것은 **CPU 여유**(프레임당 3.31 → 1.12 ms, 표시 없이 기준)와
**CPU 비용 거의 없이 도는 실시간 화면 표시**다.
근거: [`07_results/op_point/summary.md`](../07_results/op_point/summary.md) §8.4

### 2. "조용히 틀리는 것"이 반복 주제다

이 프로젝트 문서에는 **에러를 내지 않고 잘못 도는** 사례가 계속 나온다:
창 모드에서 표시가 2.6배 느려지는 것, 디코더가 프레임을 13개 넘게 붙잡으면 멈추는 것,
백프레셔 계수가 겹쳐 성능이 절반이 되는 것, 틀린 크기를 줘도 성공을 반환하는 API,
컴포지터가 평면의 색 범위(limited/full)를 뒤집어 넘기는 것, 컴포지터가 HDMI 를 잃으면 스왑체인 present 가 영원히 멈추는 것([07장](07_video_display.md) §7.9·§7.12).

이게 이 프로젝트가 계측과 검증에 그렇게 공을 들이는 이유다. ([08장](08_method.md))

### 3. 모르는 것은 모른다고 적혀 있다

"미확정", "추정", "가설"이라는 단어가 자주 나온다.
성능 수치 중에는 **인용이 금지된 것**도 있다(결함 상태에서 측정됐거나 왜곡이 확인된 값).

가장 큰 미검증 항목은 **연속 운용 발열**이다 — 모든 측정이 26초짜리라,
몇 시간 도는 운용에서 성능이 유지되는지 아무도 모른다.

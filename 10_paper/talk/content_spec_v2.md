## 6. ① 하드웨어 디코더 + 제로 카피(dma-buf)
- **다이어그램**
  - 이전(소프트웨어 디코드): 압축 영상 → [CPU: 소프트웨어 디코드] → CPU 메모리 →(가는 실선, CPU 복사 표식)→ [GPU]
  - 바뀐 경로: 압축 영상 → [하드웨어 디코더] ⇒(굵은 실선 "dma-buf")⇒ [GPU]
    - CPU는 점선으로 디코더를 지휘만 한다
    - 굵은 화살표 위에 작은 글씨로 "파일 기술자만 넘김"
- **아래쪽**
  - v1의 막대 차트 2개를 그대로 쓰되 크기를 줄인다: (a) 31.8 대 0.23~0.28, (b) 2.02 / 0.55 / 0.23~0.28. 범위 막대 방식과 라벨도 그대로
  - 한 줄 메시지(v1 그대로): 같은 하드웨어 디코드라도 CPU로 내려받으면 약 3.6배(명령행 기준 2.02 대 0.55 ms) — 비용은 디코드가 아니라 복사
  - 각주 2줄도 v1 그대로
- **노트**: v1 노트에 다이어그램 설명 한 문장을 더한다 — "위 줄은 CPU가 풀고 복사하는 경로, 아래 줄은 하드웨어 디코더가 푼 프레임을 dma-buf로 GPU에 바로 넘기는 경로다."

## 7. ② NPU가 원하는 형식(NHCW)을 GPU가 바로 만든다
- **다이어그램**
  - 이전: [GPU 전처리] → NHWC 버퍼 →(가는 실선, CPU 복사 표식 "캐시 안 되는 GPU 메모리를 바이트 단위로 읽음")→ [CPU: NHWC→NHCW 변환(NPU 런타임 내부)] → [NPU]
  - 바뀐 경로: [GPU 전처리 셰이더: 처음부터 NHCW로 씀] ⇒(굵은 실선 dma-buf)⇒ [NPU]
- **아래쪽**
  - 네이티브 막대 차트 17.6 대 3.3 (ms/프레임)
  - 미니 카드 2개: 같은 전치 루프 단독 — 일반 메모리 0.95 ms / GPU 메모리 12.7 ms
  - 한 줄 메시지: 원인은 변환 연산이 아니라 CPU가 GPU 메모리를 읽는 것
  - 각주(v1 그대로): GPU 960 MHz · 디코더 자동 스레드 · 배치 1/슬롯 2 조건
- **노트**: 다이어그램 위 줄의 빨간 표식 자리가 17.6 ms의 대부분이었고, 아래 줄에서는 GPU가 NPU 형식으로 직접 써서 그 자리가 사라졌다.

## 8. ③ 결과 해석(박스 복원 + NMS)도 GPU로
- **다이어그램**
  - 이전: [NPU] → 원시 출력 →(가는 실선, CPU 복사 표식)→ [CPU: 박스 복원 + NMS(NPU 런타임)] → 검출 결과
  - 바뀐 경로: [NPU] ⇒(굵은 실선 dma-buf "원시 출력")⇒ [GPU 셰이더: 박스 복원 + NMS] →(가는 실선 "최종 검출 몇 개")→ [CPU]
- **아래쪽**
  - 네이티브 막대 차트 3.25 대 0.94 (ms/프레임)
  - 카드 2개
    - 지연: 그대로 (79.1 대 79.2 ms)
    - 정확도: CPU 기준 구현과 같은 결과 · NPU 런타임 NMS와 IoU 0.9 매칭 0.999
  - 각주(v1 그대로): GPU 1150 MHz · 디코더 1스레드 · 배치 1/슬롯 1 조건 (7번 슬라이드와 조건이 다르다)
- **노트**: CPU로 오는 데이터가 원시 출력 전체에서 최종 검출 몇 개로 줄었다는 것을 아래 줄의 가는 화살표로 보여 준다.

## 9. ④ 최저 지연 운용 — 한 번에 한 장, 줄 세우지 않는다
- **다이어그램 (대기열 대비, 두 줄)**

    - 입력이 한꺼번에 읽힘 → [앞서 읽은 프레임들이 줄을 섬: 프레임 상자 여러 개] → [슬롯(NPU)]
    - 줄 선 구간에 괄호 표시 "슬롯 대기 — 디코드 끝 기준 79 ms의 절반 넘게(약 42 ms, 추정)"

- **아래쪽**
  - 결과 카드: 도착 기준 평균 58.4 ms · **입력 18.6% 버림** · 그 안의 입력 대기열 대기 약 14.5 ms

## 10. ⑤ CPU는 거의 지휘만 한다
- **다이어그램 (지휘 구조 + 대기 방식 대비)**

### 14. 부록 A1 — 왜 CPU 읽기만 비싼가
- **왼쪽 (약 55%): 네이티브 가로 막대 차트** "같은 V3D 메모리 1.2 MB를 읽고 쓰는 속도 (GB/s)"
  - 축 0부터, 선형
  - 막대 7개, 위에서 아래로:

    | 막대 | 값 |
    |---|---:|
    | CPU 1바이트 읽기 | 0.096 |
    | CPU memcpy 읽기 | 1.567 |
    | CPU 1바이트 쓰기 | 2.39 |
    | CPU memcpy 쓰기 | 6.05 |
    | CPU memset | 12.54 |
    | GPU 읽기 (uvec4) | 14.66 |
    | GPU 쓰기 (uvec4) | 16.03 |
  - 색 구분
    - CPU 읽기 2개: 회색 계열 진하게(문제의 막대)
    - CPU 쓰기 3개: 회색 옅게
    - GPU 2개: 강조색
  - 라벨은 값 그대로(GB/s). CPU 1바이트 읽기 막대에는 "12.82 ms", CPU 1바이트 쓰기 막대에는 "0.514 ms"를 함께 단다
  - 차트 아래 한 줄 메시지: "같은 메모리에서 CPU 1바이트 **쓰기가 읽기보다 24.9배** 빠르다 — 비대칭은 CPU 읽기 하나에 몰려 있다"
- **오른쪽 (약 45%): 원인 도식**(yEd 그림 `diagrams/appx1_why_cpu_read.png`)
  - CPU는 페이지 테이블이 이 메모리를 비캐시로 표시해서, 바이트 load마다 DRAM까지 간다. 쓰기는 모아서 보낸다
  - GPU는 자기 MMU로 같은 DRAM을 직접 읽는다
- 각주 2줄
  - 출처 공통 문구. CPU 읽기 2개는 앞선 측정(2026-10-16 stride_read)의 값이다
  - GPU 값은 디스패치당 고정비를 뺀 값(net)이다. GPU 대역폭은 V3D 메모리와 캐시 dma-heap이 ±0.3% 안으로 같다
- 노트: 같은 메모리라도 누가 어떤 방향으로 접근하느냐에 따라 100배 넘게 차이 난다. CPU 페이지 테이블이 이 메모리를 비캐시로 표시해서, CPU의 바이트 읽기는 매번 DRAM까지 다녀온다. 쓰기는 모아서 보내므로 싸다. GPU는 CPU 캐시와 상관없이 같은 DRAM을 읽는다. 그래서 설계 원칙은 "GPU가 쓴 데이터는 GPU·NPU가 소비하고, CPU는 읽지 않는다"다.

### 15. 부록 A2 — zero-copy의 대가: 캐시 일관성
- **위쪽 (약 55%): 일관성 도식**(yEd 그림 `diagrams/appx2_coherence.png`)
  - 두 줄 대비
    - "sync 생략": CPU 캐시에만 새 값이 있고 DRAM에는 옛 값 → V3D가 DRAM의 옛 값을 읽음
    - "sync 사용": END|WRITE에서 캐시를 DRAM으로 내보냄(clean), START|READ에서 캐시를 비움(invalidate) → V3D가 새 값을 읽음
- **아래 왼쪽: 표** "sync를 생략했을 때 옛 값이 보인 캐시 라인 비율 (256 KiB, 캐시 dma-heap)"

  | 시나리오 | 옛 값 |
  |---|---:|
  | CPU가 라인을 캐시에 상주시킨 뒤 씀 → GPU 읽기 | 96% (0.9635) |
  | CPU가 캐시를 채움 → GPU가 씀 → CPU 읽기 | 97% (0.9739) |
  | CPU가 평범하게 덮어씀 → GPU 읽기 | 7% (0.0699) |
  | sync를 지킴 (모든 경우) | **0** |
- **아래 오른쪽: 요점 2개**
  - "V3D는 CPU 캐시를 보지 않는다 — 제출·대기 경로에 CPU 캐시 관리 0건(커널 추적)"
  - "일관성을 만드는 장치는 `DMA_BUF_IOCTL_SYNC` 하나뿐 — 지키면 충분하다"
- 각주: 출처 공통 문구. 장치끼리 넘기는 버퍼(디코더·NPU → GPU)는 CPU가 만지지 않으므로 이 sync가 필요 없고, CPU가 읽거나 쓰는 버퍼에만 필요하다
- 노트: zero-copy는 복사를 없애지만 대가가 있다. CPU 캐시와 장치 사이의 일관성이다. 이 SoC의 V3D는 CPU 캐시를 들여다보지 않아서, CPU가 만진 버퍼를 sync 없이 넘기면 옛 값을 읽는다. 실측으로는 캐시에 남은 라인의 96~97%였다. 그래서 CPU가 접근하는 버퍼는 반드시 sync로 감싼다.

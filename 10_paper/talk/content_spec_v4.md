## 16. 부록 A3 — 전처리: CPU 대 GPU, 같은 조건

- 섹션은 v3의 "부록"이다. 목차에는 넣지 않고, 쪽 번호는 16이다.
- 디자인은 내용 슬라이드(밝은 바탕)이며, 14번 A1과 차트 글꼴·색 규칙을 맞춘다.
- 부제(작게): "1080p 디코드 프레임(SAND) → 640×640 NHCW, 같은 입력·같은 출력"

### 왼쪽 (약 55%): 네이티브 묶음 가로 막대 차트

차트 제목: "프레임당 처리 시간과 CPU 사용 (ms)"

- 계열 2개
  - **처리 시간(wall)**: 회색 슬레이트
  - **CPU 사용(전 스레드 합)**: 강조색
- 범주 5개, 위에서 아래로:

  | 범주 | 처리 시간 | CPU 사용 |
  |---|---:|---:|
  | CPU 스칼라 기준 · 1스레드 | 10.60 | 10.61 |
  | CPU swscale(NEON) · 1스레드 | 5.46 | 5.50 |
  | CPU swscale · 4스레드 | 2.62 | 5.84 |
  | CPU swscale fast_bilinear · 4스레드 | 2.11 | 3.93 |
  | **GPU 셰이더** | **1.81** | **0.081** |

- 축은 0부터 선형이다. 막대 끝에 값 라벨을 단다.
- GPU 범주는 이름을 굵게 하거나 옅은 배경 띠로 강조한다. 슬라이드 폭 전체의 장식 띠는 쓰지 않는다.

### 오른쪽 (약 45%): 단계 분해 누적 가로 막대

- 막대 3개, 단위 ms:

  | 막대 | map(dma-buf 동기화) | SAND 평면화 | 리사이즈+색변환 | 패딩 | 전치 |
  |---|---:|---:|---:|---:|---:|
  | CPU 스칼라 · 1스레드 | 0.116 | 1.169 | 8.856 (패딩 포함) | 0 | 0.433 |
  | CPU swscale · 1스레드 | 0.126 | 1.060 | 4.031 | 0.058 | 0.187 |
  | CPU fast_bilinear · 4스레드 | 0.127 | 1.065 | 0.626 | 0.059 | 0.223 |

- GPU는 막대 대신 같은 축 위에 단일 막대 하나 "GPU 셰이더(SAND를 직접 읽음) 1.757"(device 시간)로 둔다. 또는 막대 아래 한 줄 주석으로 처리한다. 둘 중 깔끔한 쪽을 고른다.
- **"SAND 평면화" 구간은 강조색**으로, 나머지는 회색 계열 농담으로 칠한다.
- 누적 막대 라벨 규칙(`ctr`/`inEnd`/`inBase`만)을 지킨다. 작은 구간은 라벨을 끄고 범례로 대신한다.
- 차트 아래 한 줄: "평면화(약 1.1 ms)는 넷으로 나누면 오히려 느려진다(1.17→1.60 ms) — GPU는 이 단계가 없다"

### 아래 (전체 폭): 핵심 메시지 2줄
- "최적화한 CPU도 처리 시간은 GPU보다 느리다 — GPU가 CPU 최속(2.11 ms)보다 **14%** 빠르다"
- "진짜 차이는 CPU 사용 — GPU 0.081 ms/프레임은 CPU 구현(3.58~10.61 ms/프레임)의 **1/44~1/131**"

### 각주 2줄
- 출처 공통 문구
- "swscale 결과는 기준 구현과 필터가 달라 PSNR 33.5~42.2 dB(비트 일치 아님). GPU는 660프레임 중 4바이트만 ±1. 실제 파이프라인에서는 GPU가 다른 단계와 겹쳐 돌고 CPU 4스레드는 다른 스레드와 코어를 다툰다(이 측정은 동기 1프레임)."

### 노트
"질문이 '그냥 CPU를 최적화하면 되지 않느냐'라면 이 장이 답이다. NEON 최적화 라이브러리로 4스레드까지 써도 처리 시간은 GPU보다 느리고, 무엇보다 CPU를 3.6~10 ms씩 쓴다. GPU는 0.08 ms다. 게다가 CPU 경로는 하드웨어 디코더 출력(SAND)을 먼저 평면으로 풀어야 하는데, 이 단계는 메모리 대역폭에 묶여 스레드를 늘려도 줄지 않는다. GPU 셰이더는 SAND를 바로 읽는다."
